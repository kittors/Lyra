# 内置能力

## 提问与引用

`ask_user` 会等待当前请求的选项或自定义回答。完全访问、自动批准和已记住的授权都不会替用户
作答；回答回到发起请求的会话和工具结果。自定义输入默认就有，工具调用写明 `allowCustomInput: false`
才不显示；「跳过问题」也默认就有。跳过、取消或超时都不生成答案，也不会授予命令或文件操作权限。

输入 `@` 可以选择文件、文件夹、技能、智能体或历史会话。会话引用以标题胶囊显示，完整会话 ID
随草稿保存，重名会话不会互相替换。文件选择保留完整路径，项目外的文件不会被误当成项目内同名文件。
智能体候选来自运行时注册表。历史转录通过 `read` 的 `session://` 地址读取，并标记为参考资料。

消息的技能与会话胶囊来自显式元数据；普通正文和标题不靠关键词删改。技能列表只授权读取已列出的
具体技能文件，不扩大文件写入范围，也不开放整个用户配置目录。


## 子智能体

Lyra 内置七种子智能体：`general`、`explore`、`review`、`verify`、`plan`、`simple`、`reason`。
设置 › 智能体在没有会话、刚新建会话或会话尚未载入时也显示这七项，可以提前选择模型和思考等级。
默认遵循定义：`general` 跟随主会话，`explore`、`verify`、`simple` 使用 `@fast`，`review` 使用
`@review`，`plan`、`reason` 使用 `@deep`；未设置角色时回退到主会话模型。保存的覆盖在下一次派发生效。

定义来自同一个 `@lyra/core/agents-builtin` 浏览器安全入口，运行时与设置页不维护两份名单。
会话能力加载后使用已合并的项目、用户和内置定义，同名项目／用户定义仍按能力层优先级覆盖内置项。

## 子智能体调度

派不派、派几个，在设置 › 子智能体调度。积极性默认跟随思考等级——等级越高越主动派活，因为
派一个子智能体的代价是一整轮模型调用加一份从零开始的上下文，而这笔账划不划算取决于这一轮
值多少钱。关掉跟随之后由五档钉死：从不派、省着派、挑着派（默认）、主动派、放开派。并发上限
是天花板，积极性低的档位会在它底下再收一道（挑着派减半，省着派只放一个），任何档位都不会
越过它。

「从不派」关掉的是模型自作主张，不是这个功能：你在消息里写 `@explore`，这一轮 `task` 就回到
它的工具表里，而且只放行你点到的那几个。点名只对当轮有效——它是一次祈使句，不是一个开关。
没点名的那一轮 `task` 根本不出现在工具表里，模型不会想要一个没见过的工具。

设置对所有会话生效，写盘后下一轮即用新值，正在跑的并发闸门也会当场改宽度，不需要重开会话。
派生深度上限与自递归拦截是安全边界，不随档位改变。见 `runtime/delegation.ts`。

## 会话级操作

两件对「这个对话本身」做的事。只有桌面端（和连着它的手机）有：CI 里跑的 agent 没有，子智能体
也拿不到——子智能体不是一个对话。设计见 [ADR-0039](../adr/0039-session-level-operations.md)。

**建议一个新会话（`spawn_session`）。** 做手头这件事时看到另一件值得单独做、但做了会把这次改动
撑大的事——没人用的代码、过期的文档、缺的测试、确认过的 TODO、顺手看到的安全问题——模型不顺手
做掉，也不只在回复里提一句，而是在对话里留一张卡片：「建议的新会话」、一个标题、一两句为什么、
一颗「开始」。卡片出来时什么都没跑，这一轮照常往下走。

点「开始」才在这个对话的项目里另开一个会话，把卡片背后那段说明作为第一条消息发出去。新会话出现在
侧栏里、自己在后台跑，你停在原来的对话里不动；对话跑在自己的工作树里时，新会话开在它所属的项目上，
不开进那棵工作树。之后卡片变成「已开始 · 打开」，点它切过去。重开应用也还是这样：新会话的记录里
写着它是从哪张卡片开出来的。× 只是在这台机器上把卡片收起来，记录还在。

**归档这个对话（`archive_session`）。** 只在你要它归档时用，比如「做完就归档」。它不当场归档——
那会把正在说话的这一轮砍掉——而是让这一轮停在这一下：这一轮收尾之后再归档，会话里没有东西在跑了
再放掉它占着的 MCP 进程和网页。界面离开这个对话，手机同步。这一轮要是被你停下或出了错，就不归档。
想找回来：设置 › 已归档的聊天。

下面四节——浏览器、索引库、钩子、移动端同步——不属于「工具」，但决定 agent 能做什么。

## 浏览器

`web_fetch` 拿到的是服务器发来的 HTML。桌面浏览器使用真实的 `<webview>`，Agent 的
`browser_*` 工具直接控制面板中可见的同一组标签，读取脚本执行后的页面，并通过原生输入点击、输入。
标签按会话隔离：每个会话看到的是自己开的那些页面，切走再切回来还是原来那一张。页面本身按最近
三个会话保留——每张页面都是一个渲染进程，更早的会话切回时重新加载，正在跑 turn 的会话不受这条
影响。销毁会话时回收对应标签。

地址栏也是搜索框：不像网址的东西直接交给搜索引擎，输入时下拉会先告诉你它打算搜还是打算打开，
并列出匹配的书签。搜索引擎在「设置 → 浏览器」里选，默认必应，也可以填自定义地址（用 `%s`
代表搜索词）。地址栏旁的「⋯」菜单集中提供新建／关闭标签、书签、检查元素、框选区域、开发者
工具、缩放与视口尺寸。只有多个标签时才显示标签行。

Agent 光标由面板覆盖层绘制，采用圆润的黑色箭头、白色描边和蓝色光晕，兼顾浅色与深色网页。
点击时显示蓝色圆环，系统开启减少动态效果时停用移动和圆环动画。坐标按网页缩放与视口适配比例换算，
光标本身保持固定显示尺寸。网页的弹窗、样式和导航不会遮住或销毁它；滚动显示视口中心的操作位置，
键盘操作保留最后位置。读取与任意 `eval` 不会虚构鼠标移动。`browser_screenshot` 截取网页内容，
不包含面板绘制的光标装饰；检查光标本身需截取真实应用窗口。

**边界**：页面内容是不可信输入。它被包在一个明说「这是不可信的」的标签里交给模型，绝不当作指令
执行。超时是硬的——15 秒不回应的求值会被放弃，新开的标签 30 秒内没接上面板也会被放弃；读回的文本上限 40000 字。

面板里的 `<webview>` 另有三道守卫（剥掉 preload、禁 node、限制能加载的协议），见
`packages/desktop/electron/window-security.ts` 的 `guardWebviews`。

## 索引库

`grep` 回答「这段文字出现在哪」，索引库回答「这个东西在哪定义的」。

在大仓库上这个差别很要紧：grep 一个 `applyDiscount` 会返回每一处调用，索引返回的是定义它的那
一行。

定义是用正则识别的，不是解析出来的。每种语言配一个真正的解析器会更准，但也要为每种语言引一条
工具链；一个认得各语言声明形式的正则，足以把 agent 带到正确的文件和行号——那是它在开始读之前
需要的全部。

在设置 › 索引库里建立和重建。

## 钩子

每个钩子是一条在工具调用前后运行的 shell 命令。工具名和参数**既作为环境变量、也作为 JSON 从
标准输入**送进去，所以钩子可以是一行，也可以是一个真正的脚本。

| 环境变量 | 内容 |
| --- | --- |
| `DW_TOOL` | 工具名 |
| `DW_EVENT` | `before-tool` 或 `after-tool` |
| `DW_ARGS` | 参数，JSON |
| `DW_CWD` | 工作目录 |

（前缀是 `DW_` 而不是 `LYRA_`，是改名之前留下的。改掉会让已有的钩子脚本失效，所以留着。）

配置项：`command`、`tools`（留空则每个工具都触发）、`event`、`enabled`、`blocking`。

**`blocking` 是钩子从「日志」变成「护栏」的那一项**：一个 `before-tool` 钩子非零退出会把这次
调用变成一个错误结果，模型能看到并作出反应。

## 移动端同步

手机上跑的不是另一套界面，是**桌面端的那一份**——由同步服务提供，在 WebView 里加载。见
[ADR-0001](../adr/0001-mobile-hosts-the-desktop-renderer.md)。

在设置 › 移动端同步里启用，扫二维码配对。

### 三条路径

| | 怎么连 | 什么时候用 |
| --- | --- | --- |
| 局域网直连 | 手机直接连桌面端的端口 | 同一个 Wi-Fi。最快 |
| 反代 | 经你自己的域名与 TLS | 有域名和反代时 |
| 中转 | 两端各自往外拨，在中转的房间里碰头 | 谁也连不到谁时 |

中转不知道你的令牌：房间号是令牌的 SHA-256，令牌本身不出现在任何发给它的消息里。但这不是端到端
加密：中转能读到、也能注入经过它的帧，拿到房间号就能进这个房间。TLS 只保护两段网络链路，挡不住
中转的运营者，所以只用你自己部署或信得过的中转。见 [ADR-0002](../adr/0002-relay-knows-nothing.md)
与 [packages/relay/README.md](../../packages/relay/README.md)。

### 手机能做什么，不能做什么

界面是全的，能力不是。每个方法手机能不能调，标在 `packages/contract/src/methods.ts` 的 `remote` 上，
`electron/sync-rpc.ts` 照着放行；不在名单上的方法对手机不存在，界面按宿主能力过滤。手机保留会话、侧聊、任务、轨迹、子 Agent，以及项目内的只读文本文件浏览；
终端、浏览器、Git、截图、文件写入和对应的桌面管理设置不会出现在手机入口中。

名单挡的是手机能直接调用哪些方法，不是配对令牌能做多少事：手机能把权限切到「完全访问」，再让 agent
在项目里跑任意命令——在手机上批准本来就是这个功能存在的理由。**配对令牌要按「能操作这台机器」来保管。**

设置也是逐字段白名单的（`electron/phone-settings.ts` 的 `PHONE_WRITABLE`）：手机能改外观、默认模型、
侧边聊天与生图模型、常用模型、推理档位、权限模式与「始终允许」、个性化、界面语言、重试、提交说明语言、
子智能体调度与各自的模型、停用插件和置顶会话；不能改 `hooks`、`scheduledTasks`、`mcpServers`，也不能
改供应商与密钥——前三样是桌面端会自己执行的命令或启动的进程。

连接、断线恢复、资源通道、完整能力矩阵和触控约束见
[移动端宿主、同步与能力边界](../architecture/mobile-sync.md)。
