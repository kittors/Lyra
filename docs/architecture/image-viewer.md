# 看图查看器：飞行、标注与「完成」

代码在 `packages/desktop/src/features/image/`：`ImageViewer.tsx` 是查看器，`flight.ts` 是飞行
两端的几何，`hand-off.ts` 是「完成」把图交给输入框，`viewer-store.ts` 是谁都能叫开它的那个 store。
真窗口探针：`e2e/viewer-flight-probe.ts`（`--wide` 换宽图），文件面板的另一条：
`e2e/image-pane-fit-probe.ts`。

## 飞行

点缩略图，图从缩略图的位置长到窗口中央；关掉，原路缩回去。两个变换各管一件事：

- **外层是飞行**。先量图在窗口中央落定时的盒子，再用 `Element.animate` 从「缩略图的样子」播到
  「落定」。中途从不按中间尺寸排版，所以大图和小图一样便宜。
- **内层是缩放和平移**。分开是为了两者不互相覆盖，也让飞行量到的永远是落定的布局盒——放大之后再关，
  照样飞回对的缩略图。

起点是 `flight.ts` 的 `atThumbnail`：**一个统一的缩放 + 一个 `clip-path`**。缩略图常是另一种比例
的 `cover` 裁切，按 cover 缩放会让图的一部分悬在缩略图外面，`clip-path: inset(…)` 把它们剪掉；
圆角半径除以缩放倍数，缩放之后正好是缩略图自己的圆角。于是第一帧就是缩略图本身——尺寸、裁切、
圆角都对得上——落地的最后一帧也是。全程不透明。

从前起步是 0.4 不透明、返程降到 0.35，用来遮那截悬在外面的裁切。在浅色对话上它读出来的是：
起飞闪一下淡影，落地前一张发白的图在缩略图上停五六帧，最后一帧「啪」地变实。裁切直接不画了，
就没什么要遮的。

缩略图读的是**元素当时的样子**（`thumbOf`），不是点击那一刻记下的矩形：返程可能是几分钟后，
对话在底下被新回复滚走了。读的是元素里那张图**实际画出来的区域**和较大的那个圆角——对话里生成
的图圆角在外层框上，附件格子的圆角在按钮上，`object-contain` 的图要按留白算。

遮罩和控件用 `starting:opacity-0`（`@starting-style`）淡入。它们以前是内联 `opacity: 1`：
新挂上的元素没有画过的起点，过渡无从开始，于是点一下窗口就瞬间暗 72%，而关的时候却是淡出的。

## 布局永远是 `<img>` 的

标注画布是**叠在图上的一层**，不是替换图的另一个元素。

这是「点编辑，图先放大到四倍再缩回去」的根因。从卡片上的「编辑」直接进标注时，同一次提交里
`<img>` 被换成还没解码的 `<canvas>`——没有 `width` 属性的画布是 300×150——而关闭后没有复位的
`leaving` 让飞行的测量推迟到了换完之后：量到 300×150，起点缩放算成 `max(420/300, 420/150) = 2.8`；
下一帧画布解码成 729×729，同一个缩放把它画成 1687px，再花十几帧缩回 729。

现在：

- 盒子由 `<img>` 决定，不管当时画布在不在、解没解码，量到的都是落定的盒子；
- 画布在解码画好之前隐藏，不会再闪 300×150 的白条；
- 解码推迟到飞行结束之后（`decodable`），不和动画抢主线程；
- 关闭完成时 `leaving` 复位，第二次打开和第一次走同一条路；
- 关闭时不先退出标注模式——那会让工具条一帧卸载、右上角冒出三个预览按钮再淡掉。标注层随其他
  东西一起淡出，图落回缩略图时就是缩略图。

## 「完成」

对话里的图（生成的、消息里发过的）标注完按「完成」，带标注的副本作为附件进**这张图所在对话**的
输入框（`attachToComposer(sessionId)` → `setComposerDraft`，分屏时不串到别的屏），光标落在输入框里。
接着说一句「照这个改」，`image_generate` 的 `#1` 就是这张标注图，走 `/images/edits` 二次生成。交出去的标注图记着它是从哪张图标注来的（`attachToComposer(sessionId, media)` → 图片块的 `from`），
画廊的生成链路靠它穿过标注那一步，见 [ADR-0034](../adr/0034-gallery-and-lineage.md)。

一路上修了三处，缺一处这条路就不通：

1. **画布被污染**。`ly-media:` 是标准 scheme，对页面来说是另一个源，画过它的画布 `toDataURL`
   直接抛错——生成图的「保存副本」从来就没成功过，异常吞在点击回调里。现在标注器经
   `files.mediaDataUrl` 拿字节：主进程用 `net.fetch` 走 `ly-media` 自己的处理函数，能读什么由那一处
   决定。没有给这个 scheme 开 CORS：预览页（模型写的 HTML）和应用在同一个会话里，开了等于让它们读走
   会话图片。
2. **附件一打字就被删**。输入框靠句子里的标记认附件，没标记的附件在下一次改字时被当孤儿卸掉；
   `composerDraft` 和浏览器的区域截图都是直接追加、不落标记。现在一律走 `marks.attach`。
3. **`#1` 指向旧图**。「本轮画的图」记在会话级的共享状态里、从不清空，几轮之前画的图一直排在
   用户刚附上的图前面。`conversationPictures` 现在把已经进了对话记录的图从「本轮」里剔掉。

## 标注：大小按屏幕算，画布按屏幕出像素

标记存在图片的原始像素里，这一条没变；变的是两件「按什么定」的事。

- **默认大小按屏幕点数定**，在图片适配窗口时的大小上算（`strokeAt`、`typeAt`、`badgeAt`、
  `mosaicBlock`/`mosaicBrush`，在 `annotate.ts`）。中档是 4pt 的线、22pt 的字、28pt 的标号、10pt 的
  马赛克格子。以前按图宽的比例算——截图是一个图像素对一个物理像素，这条规则只对它成立；一张
  1408px 的生成图适配进窗口，中档就成了 2.3pt 的线和 11.7pt 的字，比界面字还小。换算系数 `unit`
  由画布量出来交给标注器；放大时不变，在 300% 下画的和 100% 下画的是同一个标记。
- **画布的像素数跟着它在屏幕上的样子走**（`backingScale`）：不少于原图、不多于 4096²、按 1/8 取整，
  标记经一次缩放画上去。以前画布就是原图那么多像素再让 CSS 拉伸，Retina 上 0.64 个像素对一个物理
  像素，线和字都是糊的。导出不读这块画布：`render()` 在原图尺寸上用同一个 `paintAll` 再画一遍，
  所以交出去的图和原图一样大、和屏幕上看到的是同一份内容（探针量过，平均差 0.3 级）。截图浮层的
  画布本来就是一个图像素对一个物理像素，算出来是 1，它从画布直接裁图的做法不受影响。
- 文档里的画布会继承元素的 `font-variant-numeric`，而 body 上是 `tabular-nums`：画上去的数字比输入
  框里宽 12%。画布元素上显式写回 `normal`。
- 选中框、手柄、输入框的虚线在缩放的舞台里，尺寸都除以缩放，屏幕上始终是 1pt 的线、10pt 的点；
  选中的容差和手柄的抓取范围同样按屏幕点数算。

文字的几条手感，每条都对应一个实际碰到的别扭：光标落在点下去的地方（框按内边距和半行往左上挪）；
Esc 和 ⌘↵ 是写完，不是丢掉；在框外点一下是写完，不在那儿再开一个空框；靠图右边开始写，框往左长
而不是在剩下那点宽度里折成一竖条；画布按输入框的规则断行（行首不放逗号句号和闭括号，长单词按字
符断）；重新打开一段字加词，框跟着变宽，只有手拖过宽度的才保持宽度。

工具条在看图器里用和截图浮层一样的大号（36pt 按钮），能按住拖走（`useMovableBar`）：空隙处按下
直接拖，按钮上按住 320ms 再拖，松手那一下不算点按钮；拖到哪记到哪，窗口变小时夹回窗口里，放到
左下角缩放控件上会自己滑开。它按自己最窄时的宽度居中——选中东西时多出「删除选中」，往右长，
已有的按钮不挪。

## 相邻的同一类毛病

- 文件面板打开大图：适配值在 effect 里（绘制之后）才算，图先按 100% 画出来，再被常驻的 90ms 过渡
  播着缩到适配。现在适配值和可见在同一次提交，过渡在落定的那一帧画出之后才打开。
- 标注工具条上方的属性气泡：进场关键帧动的是 `transform`，覆盖了内联的 `translateX(-50%)`，前
  220ms 偏右半个身位再跳回。改用独立的 `translate` 属性。
- 编辑一张宽图且没指定比例：画的时候按方块占位，图到了再突变成 16:9。工具在详情里带上输入图的
  形状（`shapeHint`），图框画的时候就是成品的形状。
- 输入框附件托盘：带图发送时内容和展开态在同一次提交里清空，收起过渡无物可收，输入框上沿一帧
  跳下 76px。现在最后一排图（惰性）陪托盘收起，内边距放进被裁剪的那一层。
