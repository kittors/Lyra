# 对话渲染与阅读位置

对话窗口把消息数据、展示状态、滚动意图区分开，各自按会话保存。切换会话不会保留整棵隐藏 DOM。

## 行的身份

`features/conversation/grouping.ts` 将消息转换为展示行，`runKey` 是主会话与子 agent 转录共同使用的身份规则。
一条回复拆成思考行与正文行时，两行必须有不同的 key。思考行属于当前回合，后续回复的思考替换它时保持身份；
正文属于原消息；工具组属于第一个工具调用。主会话再加上 session ID，避免跨会话复用局部组件状态。

不能用展示数组的下标、流式文本长度或 `upTo` 作为身份。重复 key 不只产生警告，还会让 React 在切换后留下
无法正常回收的旧节点，表现为重复思考行、滚动范围增长和跨会话内容残留。

## 高度与挂载成本

默认挂载最近 60 个展示行，用户按需加载更早的历史。问题导航可以直接选择包含目标消息的 60 行窗口，
不用把它与最新回复之间的全部历史挂载起来；窗口前后分别提供继续加载入口。已挂载的行从第一帧使用真实高度，不使用
`content-visibility: auto` 配合估算高度。长回复与单行工具摘要的高度差异很大，200px 占位会在滚动途中
改变 `scrollHeight`，影响滚动条比例与阅读位置。

思考、工具组、整轮过程复用 `ui/layout/Collapse.tsx` 的 grid 高度过渡。首次展开才挂载内容；
思考与工具组打开后保留子树，整轮过程在收起过渡结束后释放子树，减少动态效果时立即释放。
收起中使用 inert/aria-hidden；快速反向切换不能在 transitioncancel 时卸载内容。恢复已打开的组从首帧使用自然高度。
历史转录不重播位移动画；工具折叠与状态指示仍使用既有的过渡。

## 点击与加载

侧栏行的选中必须落在点击这一帧。`previewSession` 只写 `pendingSessionId`，不用
`flushSync`——连点时强迫同步提交会把主线程锁死。不在这一帧改 `view`，也不动转录。

每一行自己问「我是不是亮的」。点一下只醒被点的那一行和正在离开的那一行。
分屏树里那片正在被替换的叶子，在 `show()` 改掉它之前仍写着上一个 id；那不是「另一格还开着」，
不能再点亮。`pendingSessionId` 清掉的同一拍就把叶子换掉，否则旧行会闪一下激活底。

停泊上一份转录、替换分屏叶子、把新消息挂上屏幕，都等到点击停手
（`SESSION_SETTLE_MS`，360ms）再做，只处理最后那个 id。连点间隔通常是
80–300ms，短于这个窗口的阈值会让每一次按键都拆掉当前转录、再挂六十行——
那才是卡死，不是行高亮。冷会话先读进 `sessionCache`，当前对话的树一直留着；
读完并且指针还停在这个 id 上，才做一次暖切换。右侧可以慢，也可以暂时还是
上一份转录；左侧不能等。较新的点击用 `selectionEpoch` 作废还没提交的那一次。

## 两种缓存

- `store/session-slice.ts` 与 `session-read.ts` 保存最多 12 份已读会话，恢复消息、工具结果、任务、审批和运行状态。
  最近访问的会话会更新淘汰顺序。重新读取相同序号的已完成日志时复用消息对象；已缓存会话在读取期间到达的事件
  不会被较旧的刷新结果覆盖。后台消息、工具、审批和结束事件直接折叠进已读缓存，标记待校准，
  不删除缓存。重新打开立即显示已更新的内容，再读取磁盘校准。冷读期间记录事件，保留磁盘历史前缀，
  合并期间到达的消息；两种读取路径都恢复子任务和运行能力。
- `features/conversation/view-state.ts` 单独保存最多 12 个会话的历史加载范围及思考、工具组、工具详情的展开选择，
  不持有消息数据或 DOM。它独立于消息缓存的更新与校准。

串行读取队列只合并磁盘读取请求，不能再次调用会话选择逻辑，否则会将用户刚恢复的状态清空第二次。
流式更新在离开会话前刷新，延迟到下一帧执行的回调也必须核对 session ID。

## 阅读位置

`ui/scroll/useFollowBottom.ts` 分别记录跟随末尾、主动回看、正在返回末尾三种意图。
保存的偏移只在对应会话的真实内容可测量后恢复；加载占位与隐藏面板不能覆盖保存的位置。
会话切换会取消旧的滚动动画与待执行的写入。滚轮、触摸、键盘及自定义滚动条拖动均参与意图判断。

`Scroller` 在内容或视口尺寸变化时先执行跟随逻辑，再测量滚动条。浏览器原生 scroll anchoring
负责同一会话中上方内容折叠、加载历史等情况；它不能替代切换会话时的显式恢复。

问题导航只包括真实用户消息，合成提示不占刻度。相同文本仍以各自消息位置定位，图片消息有文本替代。
刻度支持鼠标点击、键盘聚焦、悬停预览与当前位置提示。当前窗口内跳转使用 420ms 滚动过渡；
需要更换历史窗口时先挂载目标，再在 layout effect 中定位，避免先画一帧错误位置。
减少动态效果时直接定位；新输入与离开会话会取消旧动画。

## 首次提交与身份

新对话草稿在提交前不写盘。提交后，主进程先创建 UUID、从首条消息生成临时标题并持久化消息，
返回侧栏条目后才初始化工作区、MCP 和模型。`pendingPrompt` 表示尚未交给模型的已存消息，
`resumePendingPrompt` 单飞消费它，不再追加一份相同用户消息。

渲染器以选择代次区分不同草稿。同一草稿的创建请求合并；较早草稿的异步创建结果只更新自身条目和缓存，
不能抢走新选择。标题始终是标签，重命名、归档、删除、缓存与草稿均按 ID 隔离。
乐观用户消息同时记录所属 session ID 与原消息引用。前台和缓存中的确认都必须匹配这两个条件；
尚未创建会话的草稿 ID 为 `null`，只能由创建结果接管，不能匹配任意已存在会话的事件。
初始化过程中停止会清除待提交标记；初始化晚到也不能重新启动模型。
自动 worktree 只改变执行目录，不改变已创建的会话 ID 和日志归属。

## 页面保留

非会话页面使用 React Activity 和有界 LRU 保留。主页面、Git Tab、设置分区与扩展 Tab 分别管理
自己的访问范围；隐藏页面暂停 effects。`Scroller` 在隐藏前保存原生偏移、恢复显示前还原，
避免浏览器在隐藏时将 `scrollTop` 归零。页面入场只做短暂透明度变化，不移动内容。
空数据与未完成读取使用不同状态；缓存回访不经过 Empty，真正慢的首次读取才显示骨架。
冷会话在 `messages` 仍为空且 `loadingSession` 为真时只画 `ConversationSkeleton`，不看
`meta.messageCount`——那条计数会在数据到达前就把空的 `Conversation` 挂上去。IPC 快照会裁掉
超大工具结果和正文，完整内容留在会话日志里。转录行距由列表容器的 `gap-2.5` 统一给出，
子行不再各自声明 `mb-2.5`。

## 提问、队列与取消清单

提问/审批卡片在 composer 上方正常文档流中占位，长内容用公共 Scroller，底部操作始终可见。
收起只隐藏正文，不卸载答案草稿。推荐标记不等于默认答案；单多选在确认后提交。skip 无默认时明确表示未回答，
只有显式 defaultOptionIndex 才产生默认答案。Full Access 免除操作权限审批，不替用户回答业务问题。

队列移除项在本次 render 就保留原 key，按批次独立清理退场计时器；最后一行的高度、边框和 margin 同时收缩。
撤回编辑时 textarea 从原 px 高度过渡到目标 px 高度。排队发送按钮保留 DOM、宽度过渡，隐藏时 inert；
发送/停止/继续共用一个按钮，图标渐变，不因换形态重建按钮。

`clearsTaskPlan` 是日志中合成用户消息的明确取消标记。前台事件、后台缓存和历史投影统一清空 Todo；
取消前 runtime 等待在途工具结束，防止迟到的 todo_write 恢复已取消的清单。
