# 分屏、工具拖动与独立窗口

2026-09-19。依据用户提供的 `录屏2026-09-19 11.55.35.mov`（63.233 秒、3016×1824、60 fps）和本机 Claude 桌面应用的实际操作整理。研究只观察界面，不使用 Claude 源码。以下区分观察事实、Lyra 实现及尚未证实的范围，不能把代码参数当作竞品测量结果。

## Lyra 实现清单

### 布局与内容寿命

- [x] 单会话和多会话都经过相同的 PaneDock；第一次打开工具不替换聊天输入框。
- [x] 各工具是平面的 keyed DOM；布局树只决定几何，不决定嵌套 React 结构。
- [x] 工具和会话的实际 DOM 顺序保持稳定。仅 React key 不足以保护 Electron webview，移动祖先 DOM 仍会重建 guest。
- [x] 增加、关闭相邻会话、整会话换位时保留浏览器 guest id、页面 `performance.timeOrigin` 和表单文本。
- [x] 被拖工具暂时离开布局树时仍保持挂载，双叶变单叶也不卸载。
- [x] 预览只写内存；成功落下才提交布局，取消或卸载恢复拖动前的树。
- [x] 每个会话自己的工具排列和分隔比例存入 localStorage，刷新恢复。
- [x] 窄聊天标题栏收起快捷工具按钮，保留菜单及关闭入口。

### 拖动、缩放与键盘

- [x] 同一个 surface 通过 `popover=manual` 进入顶层；不使用 portal 重建浏览器或终端。
- [x] viewport 坐标只计算一次，不重复加上源 tile 偏移。
- [x] 指针移动由 transform 跟随；容器保留内容、圆角及浮起阴影。
- [x] 四边落点、外层边缘落点、中央空区、无效落点撤回。
- [x] 其他工具实时让位；落地回到树计算的位置。
- [x] 工具和聊天共用把手；沿排列方向立即交换相邻容器，保留尺寸；垂直方向预览，Enter/Space 提交，Escape 取消。
- [x] Alt+方向键即时移动；仅剩一个邻居时按 50/50 分割。
- [x] 分隔条拖动调整比例，双击均分，键盘方向调整，Home 均分。
- [x] pointercancel、Escape、失焦、resize、卸载清理拖动。
- [x] 失焦/resize 不等待后台动画帧，直接释放浮动顶层并恢复布局。
- [x] 局部 Expand/Collapse、Escape 恢复尺寸，不影响另一会话。
- [x] macOS 原生全屏可拖动终端和浏览器，逃离 tile 的 paint/layout containment。

### 窗口交接与状态隔离

- [x] A/B 会话 Browser 只绘制自己的 tabs，各自保留选中项。
- [x] 隐藏主窗口 Browser 缓存让出已由 tile 或独立窗承载的页；wanted/后台页仍可运行。
- [x] 弹出前同步提交页面承载权，防止主窗和独立窗同时 attach 同一 tab。
- [x] 创建窗口失败时恢复原 dock；同一 scope/kind 再次打开激活已有窗口。
- [x] 浏览器导航及新增页面状态广播给应用窗口，包括暂时没有 guest 的独立窗。
- [x] 浏览器 IPC 校验实际登记的应用窗口和主 frame，不再依赖易变的键盘焦点。
- [x] 终端每会话独立选中 pty，新会话不自动抢用另一会话正在显示的 shell。
- [x] 终端 pending command 由所属会话消费一次；弹出与返回恢复相同 pty。
- [x] 弹出记录包含完整原树、离开后的树、原邻居及方向。
- [x] 剩余树没变时精确恢复原树；期间用户改变布局时按可用邻居落位，不覆盖新布局。
- [x] 原会话已不在屏上时保留独立窗；关闭独立窗清理回家记录。
- [x] 应用退出时还没收回的面板，重启时检查当前尺寸；原会话存在但空间不足时恢复为独立窗口，保留回家记录。
- [x] 会话窗和工具窗都有置顶开关，仅操作请求方 native BrowserWindow。
- [x] 新菜单及置顶文案覆盖七种界面语言。

## 几何参数与交互事务

以下是 **Lyra 的实现值**，不是 Claude 内部参数：

| 参数 | 值 |
| --- | --- |
| 会话分屏数量上限 | 4，沿用 Lyra 现有上限 |
| 外层会话 tile 与聊天容器下限 | 420×260 CSS px |
| 工具容器下限 | 300×150 CSS px |
| 会话 dock 与窗口 dock | 使用同一可读下限；compact 手机布局仍采用单面板切换 |
| 工具拖动启动距离 | 4 CSS px |
| 把手标记 / 命中区域 | 36×3 / 64×17 CSS px |
| 把手顶部距离 | 4 CSS px |
| 容器间隙 | 每边内缩 3 CSS px |
| 分隔条命中宽度 | 9 CSS px |
| 叶节点边缘命中带 | 28% |
| 根布局边缘命中带 | 26 CSS px |
| 键盘分隔条步长 | 2%；Shift 为四倍 |
| 状态 / 几何过渡 | 150 / 220 ms，使用 Lyra motion tokens |

工具拖动的状态顺序为：按下 → 超过阈值 → 保存原树并提起 → 根据剩余树命中落点 → 预览 → 提交或撤回 → 释放顶层。预览不能写盘，也不能通过重新挂载模拟移动。

弹出快照不是强行回滚：只有当前剩余树与离开快照完全一致才恢复完整树。其余情况重新检查空间和邻居。新窗创建、源 guest 释放、原位恢复分别有明确的状态边界。

### 最小尺寸与溢出

先计算整个布局树所需的宽高，再决定能否插入。首工具在右侧放不下时尝试下方；两条轴都不足时创建独立窗口。外层会话以同样规则处理，保留当前焦点会话，其余会话及其工具转入独立窗口。恢复旧布局和缩小窗口也经过该检查，不能只限制菜单新增。

保存比例与显示比例分开。旧布局的 8%/92% 比例仍会在显示时保护 420 px 下限；放大后可以恢复用户比例。交接过程中采用满足下限的临时画布，不先压缩文字再弹窗。

收回独立窗口时重新测量目的地。空间不足就保留独立窗口；创建失败恢复原容器，期间打开的其他工具不能被旧快照覆盖。

原邻居已经关闭或弹出时，插入函数返回原树不代表归位成功。候选布局必须包含待收回的面板；旧位置不可用时重新寻找落点，没有空间则保留独立窗。创建窗口失败的回滚必须恢复面板，不能依赖已经不存在的邻居。

收回文件面板与关闭旧窗口是两个完成信号。旧窗口仍在交接最后一次编辑时，缩窗不能把它当成已经完成的溢出转移；等待对应 scope/kind 的窗口真正关闭后，以当前尺寸重新检查。

### 文件窗口交接

文件面板弹出时，主进程按真实来源窗口托管标签、当前路径、未保存修改及换行/源码显示偏好。目的窗口重新经过 `files.read` 读取磁盘内容与权限，跨窗口消息不能替代文件访问边界。

独立窗口中的编辑通过版本号确认；旧版本请求返回最新状态，只合并本次改动。源窗口继续打开文件时复用已有文件窗口，已有标签中的较新草稿优先。收回仅合并该窗口的变化，保留源窗口期间打开的其他文件；显式保存后重新读取磁盘基线，不能复活旧草稿。普通原生关闭也要等待最后一次编辑确认。

## 已定位的根因

| 现象 | 根因 | 修复与证据 |
| --- | --- | --- |
| 打开工具或提起最后一个工具后内容重建 | 单叶分支返回另一种 DOM | 始终平面 keyed 列表；UI 测试在修前实际跑红 |
| 拖动卡片偏移一整个 tile | contain-layout/paint 改变 fixed containing block | Popover 顶层；修前目标 x=272 实际 x=544 |
| 拖动后浏览器表单丢失，即使 DOM identity 没变 | React 重排父节点，Electron guest 被销毁 | 固定真实 DOM 顺序；测 guest id、timeOrigin、文本 |
| 预览时持久化布局缺少被拖工具 | preview 共用了持久化 write | 分开预览与提交；修前持久化测试实际跑红 |
| A/B 会话显示相同浏览器页与终端 | 读取全局 activeSessionId/active terminal | 使用 SessionScope，分别保存选择 |
| 隐藏主窗与两个 tile 重复挂载同一个网页 | 缓存策略不知道其他容器承载权 | 主窗 4 个重复 guest → 每 tab 1 个；真实窗口红绿验证 |
| 浏览器独立窗偶发空白或初始化失败 | IPC 只信任当时获得焦点的窗口 | 登记窗口 + 主 frame 校验；无焦点也可同步 |
| 从深层布局返回后宽度改变 | Home 只记邻居，丢了祖先分支比例 | 完整树快照；380.09375 px 弹出后仍为 380.09375 px |
| 失焦后卡片停在半空 | 取消仍依赖后台节流的动画帧 | 失焦/resize 直接结束浮动状态 |
| 聊天被压成 72 px、正文只有 24 px | 内层分屏使用了低于文字可读宽度的独立下限 | 统一 420/300 px；真窗口正文最低 372 px，输入框 370 px |
| 初次恢复旧布局没有自动弹出溢出工具 | opacity=0 的入场帧被误判为不可见，动画结束后不重新执行 | 按 inert/visibility 判断，监听保留会话重新激活 |
| 工具已弹出却在原窗重新出现 | 最后工具移走后删除内存树，hydrate 从尚未清除的存储读回旧树 | 内存保留已加载的空会话树；回归用例实际先红后绿 |
| 空间不足的工具重启后消失 | 孤儿恢复把尺寸不足误判为会话不存在，超时删除记录 | 已测量目的地不足时重新创建工具窗口并保留原记录 |
| 弹出终端失焦后输出缺行 | 主进程只给当前焦点窗口发送 terminal:data | 应用窗口广播；连接按 renderer 与 attach epoch 管理 |

## 截图保存与连续捕获

截图下载先写入当前设置指定的目录，完成后才尝试可选的剪贴板复制。系统剪贴板异常不能阻断已授权的文件保存。下载时读取主进程最新设置，不使用开始截图时的旧目录。失败保留完整选区并显示文件系统错误，成功显示实际完整路径。

未指定下载目录时使用 Electron 的 `app.getPath("desktop")`，因此遵循系统桌面位置（包括 Windows 重定向的桌面）。截图工具栏只有一个下载箭头，负责写文件；右侧「完成」使用勾号，按原设置交付剪贴板和对话。此前「完成」因为不能覆盖原图而借用了下载箭头，导致同一栏两个下载图标中，醒目的白底按钮不写下载目录、也没有保存 toast；接口测试不会发现这种图标与动作的错配。

截图浮层是复用窗口，下载锁、异步回包与离场计时器都必须归属于捕获编号。开始下一次截图、隐藏或卸载后，旧请求不能锁住新下载，也不能把新选区关闭。

`e2e/screenshot-download.test.ts` 检查中文带空格路径、切换目录、剪贴板异常以及不可写路径，已加入 Windows UI CI。它还通过真实鼠标点击设置页的「立即截屏」、框选和可见下载箭头，测量默认桌面与目录选择后的 PNG、保存提示的透明度和尺寸，以及失败原选区重试。屏幕获取边界只返回一次性 Lyra 设置窗口的真实截图 fixture；其后的启动、捕获编号、指针事件、裁图、IPC、写盘和 toast 都走产品代码。系统桌面通过 `app.setPath` 指向隔离测试目录，避免测试文件留在用户桌面。

图标回归在 0.9.16 正式包上实测失败（下载箭头对应「下载截图」和「完成」两个动作），修复后 macOS 真实窗口检查 6/6 通过，录像为桌面 `Lyra截图下载修复测试/2026-09-19T11-29-19.169Z_截图下载_6of6.mp4`。组件测试同样先红后绿，确保图片预览中的「保存副本」仍保留下载图标。

## 边界与未证实项

- 本机 native 验证为 macOS。Windows/Linux 的原生全屏、标题栏、置顶需要对应平台复验。
- 没有证据可声称 Claude 的像素、动画曲线、所有极端排列和未知上限已逐一相同；Lyra 保留自己的主题与字体 tokens。
- 工具在同一窗口内拖动保持浏览器执行上下文。跨 native 窗口弹出会重新创建 webview，保留 URL/tab 归属；任意网页的内存状态和导航历史不保证完整迁移。
- 工具不因指针越过会话边界而转移所有权；跨会话松手撤回。不同会话可以各自打开工具。
- 终端保留已有“所有运行 shell 可从标签访问”的行为，隔离的是默认选中项；没有禁止用户手动选择同一个 shell。
- 文件编辑器仍沿用原有共享文件 store，不是每个 scope 独立的多项目编辑工作区。跨窗口交接保留标签与未保存修改；CodeMirror 的撤销栈、光标与滚动历史未跨 renderer 迁移。
- 侧栏拖出整个 native 窗口自动创建新窗口并未据此实现；New window 通过明确菜单入口创建。
