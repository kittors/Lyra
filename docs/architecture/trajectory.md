# 轨迹与任务执行记录

轨迹读取会话库里的记录，不维护第二份执行历史。任务面板按调用 ID 定位同一条轨迹，
输入、结果、时序和原始输出来自运行时记录。旧日志中没有记录的信息保持缺失，不推测补齐。

## 手动压缩为何只有消息数量

`SessionLog` 原先已经保存 `command_status` 和包含摘要的 `compacted`，但轨迹投影忽略
前者并丢弃后者的 `summary`。因此截图中的 `597 → 169` 不是完全没有记录，而是用户
无法辨认它对应 `/compact`，也不能检查命令生命周期、摘要和耗时。

投影现在按命令 ID 合并开始、压缩结果和结束，形成一个稳定条目。成功、失败、取消、跳过
均可查询；轮次之间执行的手动压缩独立展示，不伪装成模型回复。自动压缩保留数量与摘要。
前端在持久事件到达时刷新，覆盖手动命令、自动压缩和执行中的工具事件。

## 记录与投影

- `request` 保存供应商、模型、思考设置和输入消息数，关联当时的系统提示词及工具 schemas。
  回复完成后补充用量、结束原因、总时长、首 Token 等待与生成时间；重试原因单独保留。
- `tool_start` 与 `toolResult` 按父 Agent 和调用 ID 配对，关联输入、完整已记录结果、
  结构化 details、图片和实际工具耗时。模型生成调用所用的时间不算作工具执行时间。
- 子 Agent 的系统上下文、步骤、请求、消息和最终回报持久化，保留父 Agent ID 和实际模型。
  子 Agent 消息不混入主模型历史，相同 steering 对象只记录一次。
- token delta 和重复的工具输出片段只用于实时显示，不重复写入会话记录。流式回复另存为
  可恢复的残留，提交时删除，见 ADR-0032。
- 先处理 `truncate` 再投影，撤回的结果不能继续改变保留调用的状态。正在运行的会话保留
  `running`，冷读未完成记录显示 `interrupted`；明确的运行错误和用户取消使用各自状态。

代码入口为 `core/src/trajectory/{read,entries,project}.ts`，浏览器只从
`@lyra/core/trajectory-view` 导入纯展示逻辑。

## 面板交互与性能

轨迹使用工具栏、常驻 Canvas 时间轴、账本和面板内详情。时间轴保持真实时间比例，三个缩放操作
固定占位；画布折叠不卸载。首次高度不小于 400px 默认展开，可主动折叠。高度低于 240px 时
收起画布，低于 160px 时让位给记录，放大停靠面板即可恢复时间轴。

类型、状态和全文搜索真正筛选账本；拖选时间范围只聚焦匹配记录，不移除其他行。拖动期间本地
预览，松手后提交，点击空白不选择附近其他泳道记录。方向键预览、Enter 查看，平移滑块提供可见入口。
选择记录、聚焦范围和离开列表底部会暂停跟随，新记录提供返回底部入口。

详情在面板宽度达到 720px 时与列表并排，窄面板替换账本区域，列表实例和滚动位置仍保留。
宽度判断使用容器查询而非整窗宽度。详情可调整宽度，返回、前后记录与更多操作始终在固定头部；
内容、信息、原始三个标签分离阅读与结构化数据。更换记录或宽度不重建整个 inspector。
任务面板的定位请求找到工具调用后只消费一次，返回会话不会重复打开旧记录。

账本使用 36px 固定行高和每侧 8 行 overscan，保留键盘焦点行。详情文本每页 4000 字符，
搜索可以定位命中页，复制仍复制完整文本。子 Agent 的关联列表只展示前 20 项，按父 ID
可以查询全部。图片沿用应用的预览器。

读取 hook 先订阅再读取，同一时刻只有一个请求，期间到达的事件合并后补读。四会话 LRU
避免回访闪空；会话切换使旧请求失效，不能覆盖新会话。读取失败显式展示并允许重读。
刷新使用 `sessions.trajectoryChanges(projectId, sessionId, cursor?)`，返回 `cursor`、
`reset`、`upserts` 和 `removals`。首次读取或服务端缓存换代时全量替换；之后按稳定条目 ID
替换、追加或删除。游标属于客户端，桌面与手机可独立重放同一批变化，互不消耗更新。

服务端保留四会话 LRU。`SessionStore.readChanges` 的游标记着库的标识、会话 id 和已读到的最大
`seq`，只取之后追加的记录——记录只追加不改写，已读的前缀不会变；存储观察器透传这项能力。没有新记录且运行态
未变化时不再投影，也不传正文。有追加或运行态改变时复用现有投影器，只返回变化条目，未改变
条目保持对象身份。`truncate` 先撤回尾部记录再投影，因此旧调用会同步失去已撤回的结果；
会话被删除、库被换掉（标识对不上）和缓存淘汰会使旧游标失效。

全量 `sessions.trajectory` 与权威导出仍保留。初次读取仍需完整投影，新记录到达时仍会重新
投影保留历史；增量协议减少磁盘扫描与传输，不等同于无限容量或后端分页。

## 原始输出与导出边界

前台与后台 bash 将原始输出按顺序写到会话 scratch 的 `tool-output/<UUID>.log`，文件权限
为 0600，模型仍接收有界预览。结果携带文件路径、完整性和写入错误，界面可打开原始文件。
这避免把巨量输出反复塞进模型上下文或会话记录。没有会话 scratch 的独立工具调用不写用户目录。

`sessions.exportTrajectory` 只接受项目、会话和条目 ID，由主进程重读权威记录，导出 JSON
或 Markdown 临时文件。原始输出路径必须来自记录，且 `realpath` 后用 `path.relative`
验证在当前会话目录内；渲染进程不能指定任意读取路径。导出只通过既有 artifact 机制授权读取。
运行中的导出沿用主进程掌握的运行状态。

原始日志沿用 scratch 清理策略，30 天后可能清理；会话记录中的预览仍保留。
文件查看器沿用 512KiB 预览上限并提示截断，完整原始文件可通过路径访问。取消时外层工具
可以先返回取消结果，因此极早取消的记录不保证含原始输出路径。没有记录的历史子 Agent
内容、工具时序和早期被截掉的输出无法恢复。

## 参考范围

对照 [deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) 的
`packages/client/ui-trajectory`，参考版本为
`d347e703908d0406b7a7ef80e3a0e594d86b2215`。阅读了记录契约、压缩定义、工具栏和组件说明。

| 参考能力 | Lyra 对应实现 |
| --- | --- |
| 轮次、步骤与账本 | 轮次折叠、步骤索引、虚拟列表 |
| 模型、工具与嵌套记录关联 | 请求、输入输出、父 Agent 和调用 ID |
| 详情 inspector | 时序、用量、错误、结构化数据、图片、完整复制 |
| 时间概览与区间选择 | 常驻 Canvas 时间轴、范围聚焦、固定缩放、键盘浏览、面板内详情 |
| 轮次间压缩 | 命令生命周期、摘要、前后数量、状态 |
| 长记录浏览 | 列表虚拟化、尾部跟随、详情分页、全文搜索 |

这是接入 Lyra 现有运行时的对应能力，不是兼容 harness 的记录格式。当前没有记录每次 HTTP
重试的原始网络载荷，也没有额外测量自动压缩的开始、失败及模型用量；这些不能当作已实现。

## 验证

`trajectory-lifecycle.test.ts` 的命令断言和真实 Electron 压缩用例均先红后绿：修复前只读到
数量条目，修复后可以检查 `/compact`、摘要、状态和耗时。运行时测试检查持久 schemas、
请求、子 Agent 消息和步骤；导出测试检查跨项目、未知条目、越界路径和运行中状态。
组件测试覆盖全文查询、事件积压、会话切换时旧响应隔离、错误显示和重新读取。
补充红绿验证发现时间轴点击只比较横向开始时间，会选中另一行的模型或工具；命中现在同时
检查泳道和实际时间区间。用户取消的外层工具结果原先只有错误文字，现保存 `cancelled`
字段，轨迹可与真实执行错误区分。
全量检查还捕获了启动取消的写入竞态：`abort()` 的无等待 `agent_end` 落盘可能晚于首条
提交完成和会话清理。取消记录现在由提交流程等待完成；受控写入门闩测试先复现提前 resolve，
再验证修复，未用重试删除目录或延迟掩盖竞态。

真实应用 E2E 使用隔离 profile、本地合成模型服务和合成 JSONL，经正式运行时、IPC 和 UI
渲染。2500 次工具调用产生 7503 条轨迹；截图不是另外绘制的页面。应用截图存于
`/tmp/lyra-trajectory-final/`，测试 profile 退出时清理。Windows UI CI 已登记相同用例，
本机未运行 Windows，不把 macOS 验证称为 Windows 实机验证。
