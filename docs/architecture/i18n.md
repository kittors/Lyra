# 界面国际化

Lyra 的界面语言由 `Settings.uiLocale` 持久化。可选值为 `system`、`zh-CN`、`zh-TW`、`en`、
`fr`、`ru`、`ko` 与 `ja`。`system` 保存的是跟随系统这个决定，不会把某次检测到的语言写回设置。

## 三个宿主

桌面渲染进程的目录在 `packages/desktop/src/i18n/`。`I18nProvider` 解析 BCP 47 系统语言，提供
文案、数字和日期格式化，并在切换时更新 `<html lang>`。切换语言只触发 React 更新，不重载窗口，
因此不会清空草稿、滚动位置或已打开的面板。

Electron 主进程不能依赖渲染进程。原生菜单、文件选择器、系统通知和主进程错误使用主进程自己的
小型文案目录，语言来自同一个 `Settings.uiLocale`；选择 `system` 时读取 `app.getLocale()`。

Expo 原生外壳在 `packages/mobile/src/i18n.ts` 中维护配对、扫码、断线与错误页文案。配对完成后，
手机 WebView 承载桌面渲染进程，并通过同步设置取得同一个 `uiLocale`，所以两端显示一致。

`packages/core` 不是宿主，不持有界面文案，也不读 `uiLocale`。它产出的、要给人看的判断带一个码，
宿主按码在自己的目录里找句子：审批卡上的风险说明是 `ApprovalRequest.risk.code`，渲染进程的
`risk.<码>`。core 自己那句中文措辞只留给日志、轨迹和发给模型的文本。理由见
[ADR-0026](../adr/0026-core-names-the-rule-hosts-say-it.md)。

## 翻译边界

只翻译 Lyra 自己的菜单、按钮、设置、状态和错误说明。以下内容始终保持原文：

- 用户消息与 Agent 回复
- 代码、文件正文、终端输出与 Git diff
- 网页内容、工具输出与外部服务返回的正文
- 用户自定义的模型、供应商、命令、技能和规则名称

## 回退与字体

系统语言按语言族匹配。繁体中文同时识别 `zh-Hant`、`zh-TW`、`zh-HK` 与 `zh-MO`，其他中文
地区使用简体中文。不支持的系统语言回退英语。文案目录缺键时回退简体中文，测试要求七套桌面
目录拥有完全相同的键，正常构建中不会依赖这个回退。

`<html lang>` 还负责选择 CJK 字形。繁体中文、日文与韩文各使用对应的系统字体族，俄文使用
Inter 的 Cyrillic 与 Cyrillic Extended 子集，避免同一行混入不同字形风格。

## 数量与复数

带数量的句子把数量写成 `{n}`，调用时传数字：`t("archived.chatCount", { n: 1 })`。词条可以按 CLDR 复数
类别各写一句，用哪一句由 `Intl.PluralRules` 决定（`i18n/plural.ts`）。`translate()` 与 `t()` 都经过
`translateIn()`，两条路选出的一定是同一句。

```ts
"archived.chatCount": { one: "{n} conversation", other: "{n} conversations" },          // en.ts
"cleanup.confirmSome": { one: "Удалить {n} разговор?", few: "Удалить {n} разговора?",   // ru.ts
	many: "Удалить {n} разговоров?", other: "Удалить {n} разговора?" },
```

- 英语、法语写 `one` 与 `other`，法语的 `one` 包括 0。俄语写 `one`（1、21、31…）、`few`（2–4、22–24…）、
  `many`（0、5–20、25…）与 `other`（小数）。简繁中文、日语、韩语只有 `other`，一律写普通字符串。
- 只有 zh-CN 源句含 `{n}` 的键能写成复数形式，其他键写了是类型错误；`other` 必填。
- 不随数量变形的写法同样可以：俄语的 `сообщений: {n}` 对任何数量都通顺，就不必拆开。调用方先格式化过的
  数量（`toLocaleString()`、1.2K）只认得出纯数字，其余都按 `other`，所以这类句子在俄语里要用不变形的写法。
- 一句话只有一个决定变形的数量。两个数量都要变形，就拆成两个键：`usage.dayUsed` 按会话数变形，token 数由
  `usage.dayTokens` 先译好，再填进它的 `{tokens}`。
- 决定变形的数量必须叫 `{n}`。叫 `{count}`、`{total}` 的不会被选形式，`t()` 的类型也管不到变量名——调用处
  漏改，界面上就原样印出 `{n}`。改名要连调用处一起改。
- `packages/desktop/test/i18n.test.ts` 检查每一种形式的占位符都和源句一致、每种语言写齐整数会用到的类别且
  不多写。英文目录里「计数后面一两个词内跟着复数词（或写成 `device(s)`）」的普通字符串会被当成漏写了 `one`，
  例外要写明理由。计数指 `{n}`，以及中文源句里后面跟着量词的变量（「{total} 行」「{requests} 次请求」）。

## 新增文案

1. 在 `packages/desktop/src/i18n/messages/zh-CN.ts` 增加语义化 key。
2. 同步更新另外六套桌面目录，保留变量名与标点含义。
3. 组件通过 `useI18n()` 取 `t()`，不要根据当前语言写条件分支。
4. 原生移动外壳文案在 `packages/mobile/src/i18n.ts` 同步更新。
5. 新增风险规则：在 core 的 `RISK_REASONS` 加码与中文措辞，七套桌面目录各加 `risk.<码>`，
   占位符与中文措辞一致。
6. 运行目录完整性测试，并在真实窗口中检查最长的法语和俄语文案是否裁切。
