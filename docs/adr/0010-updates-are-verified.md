# ADR-0010：更新包核对摘要，验不了就不装

- 状态：已采纳
- 日期：2026-09-03
- 相关：`packages/desktop/electron/update-checksum.ts`、`.github/workflows/release.yml`

## 背景

自动更新原本只检查两件事：下载地址以 `https://github.com/` 开头，文件长度与 release 说的一致。

前者信的是来源，后者能抓住半截的下载。两者都抓不到「完整地、从正确的域名、到达的不是构建出来
的那个文件」——中间某个代理改写了响应，某个缓存被投毒，某个镜像被人立起来。

而这是整个应用里唯一一个下载完会被解包并运行的文件。

## 决定

release 用 `sha256sum *` 生成 `SHA256SUMS` 一并发布。客户端下载完、**改名之前**核对。

没有校验文件的 release 一律拒装。

## 后果

**得到的**：从 GitHub 到这台机器之间的一切都被覆盖住了。

**没得到的**：这不是一条能扛住 GitHub 账号被攻破的信任链——摘要和文件来自同一个 release、同一
条 TLS 连接。它不打算解决那个问题。

**「验不了就不装」是刻意的。** 0.8.36 及更早的 release 都没有校验文件，所以它们装不上。更新
检查只指向 latest，所以实际影响只有一次：从 0.8.36 更新到下一个版本时，那个版本会带上校验文件。
「我们没法验证」不是「可以不验证」的理由。

四种失败分开报——没发校验文件、文件不在清单里、取不到校验文件、摘要对不上——因为对读到的人
意义完全不同。都归成「更新失败」的话，网络抖一下会被报成安装包损坏。

dry run 里跑同一步并 `sha256sum -c`。少了它，第一次真发布才会发现 SHA256SUMS 没生成，而那时
tag 已经推出去了。
