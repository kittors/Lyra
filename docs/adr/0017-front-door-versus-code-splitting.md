# ADR-0017：整屏视图不进功能域的出口

- 状态：已采纳
- 日期：2026-09-03
- 相关：`packages/desktop/src/app/App.tsx`、各 `features/*/index.ts`

## 背景

给 21 个功能域建了 `index.ts` 出口，规则是「跨域只走前门」。顺手把 `app/App.tsx` 里的四个
`lazy()` 也改成了走出口——看起来一致。

它悄悄取消了懒加载。出口本身被别的域静态引着，所以打包器从入口就能到达整个域，于是把它并回了
主 chunk。`lazy()` 照常工作，`Suspense` 照常显示加载态，只是那些代码早就在包里了。

主 chunk 从 1.69MB 涨回 2.32MB，行为一模一样。

## 决定

`lazy()` 直接指向组件文件，并且把这四个整屏视图从各自域的出口里移除。

理由不是「出口该薄一点」这种偏好：**一个只有壳会打开的整屏界面，本来就不是这个域对外的接口**。
`PluginsView` 不是别的域会用到的东西，它是应用的一个屏幕。

`scheduled` 移除之后出口空了，那个文件就删掉。没有对外接口的域不需要一扇门，`pnpm arch` 照样
拦着别人往里伸手。

## 后果

主 chunk 2.32MB → 1.61MB，四个视图各自成包。

**这类回归改不了任何行为**，测试全绿、界面正常、点击照常——只是包大了 630KB。所以它靠
`scripts/bundle-report.mjs` 的基线看着，而不是靠人注意到。

手机是这件事真正的代价方：它通过网络加载同一份包，走中转还要跨两次公网。
