# ADR-0042：手机有自己的外框——一屏一页、菜单从底边升起、返回键一次关一层

- 状态：已采纳
- 日期：2026-10-16
- 相关：desktop `src/features/split/PhoneTopBar.tsx`、`src/features/dock/PhonePaneHeader.tsx`、
  `src/features/dock/PhonePanelGrid.tsx`、`src/features/settings/PhoneSettings.tsx`、
  `src/features/composer/PhoneTurnSettings.tsx`、`src/ui/overlay/sheet.ts`（`Popover` 的弹层形态）、
  `src/mobile/edge-back.ts`、`src/styles/phone-chrome.css`、`phone-sheet.css`、`phone-settings.css`；
  mobile `src/bridge.ts`（`layerDepth`）；测试 `test/ui/phone-chrome.test.ts`；
  现状说明见 [docs/architecture/mobile-sync.md](../architecture/mobile-sync.md)

## 背景

手机跑的是桌面端那一份界面（ADR-0001），手机上的样子靠 `phone*.css` 在桌面的结构上改：把控件放大到 44pt、
把 hover 换成长按、让开安全区。桌面端之后几轮重构（dock、分屏、窗口外框 ADR-0031）改了 DOM，那些规则一条条落空：
`main.ly-opaque` 不再存在，会话顶栏的六个按钮钻到了状态栏底下；面板卡片的描边和圆角留在手机上，整屏像一张卡；
输入框外面那层托盘和输入框叠成两张卡；侧栏开关的位置是内联样式，样式表的避让规则压不过它。截图里用户圈出来的
就是这些。用户原话：「明显你没有考究移动端的交互设计的，很多都是照抄的 pc 端的，太多按钮是不适合移动端的，需要
充分利用移动端的触摸特性才对」。

在桌面的结构上继续补选择器，下一次桌面重构还会再坏一遍；而且补出来的仍是一扇缩小的桌面窗口：顶上一排图标、
菜单挂在按钮旁边、设置页有一个藏在抽屉里的章节列表。

## 决定

**一、外框是手机自己的，内容是共用的。** 对话、输入框的输入逻辑、各面板的内容、设置的每一页照旧共用；外面那一圈
由手机专门的组件画：会话顶栏 `PhoneTopBar`（开抽屉、标题、新对话三样，标题居中，点它升起会话的弹层）、面板页的
栏 `PhonePaneHeader`（‹ 返回、名字）、设置 `PhoneSettings`（大标题下的分组列表，点一项推入那一页，「‹ 设置」返回）。
桌面的组件在 `onPhone()` 时整个换成这些，而不是在桌面组件里散着改——桌面那边再怎么重构，手机这一圈都不跟着坏。
面板在手机上画成平的（`DockPane` 的 `flat`）：一次只显示一个面板，卡片的边框在手机上只是一圈围着整个屏幕的线。

**二、锚在控件上的菜单从底边升起。** `Popover` 多一种形态：贴底、全宽、背后压暗、可以往下拖收起，层级、Esc、
点外面收起照旧。是不是这种形态由宿主的样式表声明（`--ly-menu-sheet: 1`，只在手机且窄屏时），`ui/` 只读这个变量——
它是叶子，不能问自己在哪个宿主里，宽度缩放（`--ly-menu-width-scale`）早就是这么做的。几十个菜单（模型、推理强度、
权限、项目、分支、会话、通知、设置里的下拉）一处改完。挂在一个点上的菜单——长按出来的——不变：它说的是被按住的
那一行，弹层会盖住它。

**三、返回键一次关一层，按原生端已经认的规矩数。** Android 返回键由原生壳里注入的脚本数「开着几层」：没被 inert
的抽屉，加上没被 inert、也不带 `data-pane` 的 `aria-modal` 元素，然后发一次 Esc。那段脚本装在用户手机的 App 里，
界面是桌面端送过去的——新界面必须说旧壳听得懂的话，不能等壳更新。所以弹层带 `aria-modal`；面板页的 `aria-modal`
挂在它的栏上而不是面板容器上（容器带 `data-pane`，会被跳过）；设置本身和推进来的一页各算一层。每一层都在 Esc 上
退回自己那一步：弹层收起、面板关掉、设置页退回列表、列表回到会话。抽屉开着时 Esc 先关抽屉。

**四、手势替掉按钮，同一个手势在不同地方说同一件事。** 从左边缘往右滑：在会话上拉出抽屉，在推进来的页面上把这一页
送回去（`edge-back.ts`，判定和抽屉共用 `drawer-gesture.ts` 的门槛与甩动）。弹层往下拉收起。长按出菜单。抽屉里的
会话行**不做**左滑出操作：抽屉自己往左推就收起，两个手势抢同一个动作；行上的操作在长按菜单里。

**五、输入框一行三样。** 附件、模型、发送。推理强度（常改的，一排选项）、权限模式、生图模型放进模型的弹层
（`PhoneTurnSettings`）；胶囊上画着推理强度，完全访问时亮红点——它从不悄悄地开着；胶囊的无障碍名称说出这两样。
桌面截图在手机上去掉：它截的是桌面的屏幕，拿着手机的人看不见。

**六、手机上不出现的东西。** 问题轨道（左边缘那列刻度：它在抽屉手势的起点上，而且是指针的工具）、在新窗口打开、
最大化、拖动面板的把手、模型菜单里的数字快捷键、只有一个供应商时的分组头。

## 后果

- 手机的样子由几个手机组件和 `phone-*.css` 决定，不再依赖桌面结构里某个类名还在不在；`test/ui/phone-chrome.test.ts`
  在组件层守着这几样，`e2e/phone-copy-fit.test.ts` 在真 renderer 上量七种语言、三种宽度。
- 弹层是 `Popover` 的一种形态，不是另一个组件：菜单的内容、行为、嵌套关系只有一份；新加的菜单在手机上自动是弹层。
- 平板（非窄屏）保留菜单挂在控件旁边、面板并排，面板栏是 ✕ 而不是 ‹。

## 什么时候重新考虑

- 原生壳的 `layerDepth` 换成别的协议时，第三条要跟着换——那时可以不再借 `aria-modal`。
- 如果要在抽屉里给会话行加滑动操作，先解决和抽屉收起手势的冲突（比如只在列表区域内让横滑归行）。
