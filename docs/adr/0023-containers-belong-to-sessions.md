# ADR-0023：面板只属于会话，窗口本身没有面板

- 状态：已采纳
- 日期：2026-09-24
- 相关：`features/dock/pane-store.ts`、`dock/DockView.tsx`、`dock/popout.ts`、`dock/persist.ts`、`split/SplitWorkspace.tsx`、`split/SplitPane.tsx`、`split/SplitChrome.tsx`、`split/session-drag.ts`、`browser/browser-store.ts`（`useBrowserPages`）、`app/session-scope.tsx`、`store/subAgents.ts`
- 取代：[split-window-conflicts.md](../architecture/split-window-conflicts.md) 里「两层容器」这个前提；那份清单的 C0、C1 都出自它

## 背景

面板（任务、浏览器、终端、文件、Git……）从前有两个家：

- **窗口一层**：`DockView` 包住整块主区域，单屏时的会话、多屏时的整个分屏，都只是它的
  conversation 槽。布局按「当前会话」存在 `dw:dock:<会话>`。
- **每屏一层**：分屏之后每一屏有自己的 `PaneDock`，布局存在 `dw:panedock:<会话>`。

单屏时只有窗口那层在用。分屏一开，窗口层并没有消失，里面装着进分屏之前就开着的面板，横跨所有屏。
用户报来的两张截图都是它：

1. **分屏时，原会话的任务面板独占整个窗口的右侧**，两屏都挤在它左边。它属于窗口，不属于任何一屏。
2. **关掉一屏回到单屏，浏览器嵌在标题栏底下，工具条悬在它上方。** 单屏的标题栏属于窗口层的
   conversation 槽，浏览器属于那一屏的 `PaneDock`，两层叠在了一起。

这不是两个 bug，而是一个模型问题。围着两层打的补丁已经攒了一长串：

- `dw:dock:at` 记窗口层此刻认哪把钥匙；
- `firstSession` 决定分屏时用谁的布局，`screens > 1` 又让它提前返回；
- `openScopedPanel` 分三条路（已经在窗口层的就留在窗口层……）；
- 浏览器缓存要知道「窗口层和各屏各自承载着哪些页」；
- 会话拖拽的落点只能按整块网格来算；
- 从会话内容里打开面板的调用点有 17 处。

每一个补丁单看都对，合起来却是一个要先解释才会用的界面。同样是「打开任务」，单屏和分屏落在
不同的层；分屏之后再回到单屏，又是另一副样子。

参照 Claude 桌面版（见 [split-view-interactions.md](../architecture/split-view-interactions.md)
的 R01、R17）：分屏的每一边都是一个会话，工具在会话里面；Expand 只填满所属的会话。

## 决定

**面板只属于会话。单屏是只有一屏的分屏。窗口本身没有面板。**

**一、一个 store，一个渲染器。** 所有布局都存在 `usePaneDock` 里，按会话区分（scope 就是会话 id，
空白对话是 `@draft`）。每一屏一个 `DockView`：由 `SplitPane` 画，`SplitChrome` 作为对话那一格的
标题栏传进去。窗口层的 `useDock`（`dock/store.ts`）和 `split/PaneDock.tsx` 删掉。

**二、单屏和分屏走同一条路。** 单屏时 `SplitChrome` 只是不显示标题和关闭按钮。所以单屏时面板是满高的，
标题栏只盖住对话那一列；分屏时每一屏也各自这样。

**三、面板开在它所属会话的那一屏。** 工具条、快捷键、从内容里打开（`openScopedPanel`）都落在
「这个会话的那一屏」。如果会话此刻不在屏上——比如弹出去的面板点「收回」时，原会话已经被换走了——
就先把会话请回屏上（`provideReveal`），而不是塞到别处。旧版记下的 `dock: "window"` 收回记录，
收回到当前那一屏。

**四、内容按屏取，不按焦点取。** 任务、子代理、轨迹、交付卡片、浏览器标签……每一屏都读自己会话的
数据（`SessionScope` / `useScoped*`）。不在焦点上的会话，子代理名单保留在 `rosters` 里。

**五、网页不换父节点。** `<webview>` 一旦换了父节点就会重新加载。每一屏都挂着自己的浏览器面板，
关闭时只是隐藏（opacity 0 + inert），并且始终承载自己会话的页面。不在任何屏上、但还要保持加载的页面
（最近看过的、智能体正在操作的），由在屏上最久的那一屏（`host`）承载。哪一屏承载哪些页面与焦点
无关：切焦点、开关浏览器面板都不会搬动页面。

**六、旧数据只合并一次。** 读取一个会话的布局时，如果旧的 `dw:dock:<会话>` 还在，就以它为底，
把 `dw:panedock:<会话>` 里多出来的面板并进去，写回之后删掉旧钥匙和 `dw:dock:at`。一个面板都不会丢。

**七、刚发出的空白对话保留它的布局。** 第一条消息发出之后，这一屏的 scope 从 `@draft` 变成新 id。
而在空白对话里点开一个旧会话，scope 也是这样变的。这两种情况靠 `draftBecame` 区分：只有前者会把
空白对话里摆好的面板带过去。

**八、工作区不随别的页面拆掉。** 插件、拉取请求、已安排这三个页面由 `RetainedViews` 保留，工作区
（整个分屏）不放在里面（`App.tsx` 的 `Workspace`）。`Activity` 收起一页时，除了 `display: none`，
还会跑完每个 effect 的清理。而工作区的 effect 正是维持各屏存活的东西：一屏忘掉自己的尺寸，它的网页
就会交给别的屏，来回各重新加载一次，表单里打的字也没了；它的终端、文件树和其余面板则会整批卸载。
从前单屏的面板放在 `RetainedViews` 外面的窗口层，所以单屏时看不出这个问题；面板归屏之后，这个问题
第一次落到了单屏上。所以工作区改用设置页收起整个外壳的那种办法（见 `Shell`）：不可见、脱离文档流、
设为 inert，版面盒子保持原样。这样每段转录的滚动位置和每一屏量出来的尺寸都不会动；它收在后面时，
也不接受会话拖放（`SplitWorkspace` 的 dropper 看到自己在 inert 里就放弃），免得在人看不见的地方被分屏。

拖拽的规则也跟着简化：

- **从侧栏拖会话进来**：落点按指针下的那一屏算，取离指针最近的一条可行边；已经四屏时改为替换；
  拖一个已经在屏上的会话，就是把它移过去（不再弹出独立窗口）；放不下时明确写「放不下」。
  按 Escape 取消。在网页上松手也会当场落下：拖拽期间，所有面板都不接受命中（`inertPanes`），
  `BrowserPage` 也不再显式声明 `pointer-events: auto` 把这条规则顶掉，网页因此不会再吞掉 pointerup。
- **点击侧栏里的会话**：替换当前焦点所在的那一屏。
- **面板放不下**：照样放进去，只是画得挤一些（沿用「放不下不再交接给窗口」那一节的做法）。

## 没有做的

- **没有保留「窗口层面板」作为可选项。** 只有一屏时，它和会话层没有区别；多屏时，它就是截图 1
  的样子。找不到它合理的用法。
- **没有做跨屏拖动面板**（C4）。每一屏一棵树之后，这件事仍然是「从一棵树里摘出来、放进另一棵树」，
  而且已经有现成的替代做法：在目标屏上直接点那个按钮。
- **非会话页面**（插件、拉取请求、已安排）不进分屏，也没有面板——它们不属于任何会话。这些页面由
  `SoloScreen` 来画：顶上一条 44px 的拖拽带，页面自己的标题行提到这条带子里。

## 后果

**得到的**：

- 截图 1 和截图 3 的状态不再可能出现：每个面板都属于某一屏。
- 单屏和分屏来回切换时，面板跟着会话走：分屏时在哪一屏，回到单屏后仍在那一屏里，并且满高。
- Expand 只填满自己那一屏（R17），另一屏不受影响。
- 刷新后每一屏的面板都能恢复，不再有「窗口层该认哪把钥匙」的问题。
- 关掉再打开浏览器不会重新加载，在任何一屏上都是如此。
- 去插件、拉取请求或已安排页面看一眼再回来，网页不会重新加载，终端也不会重建（第八条）。
- 删掉了 `dock/store.ts`、`split/PaneDock.tsx`，以及上面列出的那一串补丁。

**付出的**：

- 一次性迁移（第六条）。合并时以窗口层为底，同一个面板在两边都存在时，以窗口层的位置为准。
- 每一屏的浏览器面板一直挂着。每个会话自己的页面在它上屏期间都保持加载，即使面板关着也一样。
  最多四屏，而且这些页面本来就是在屏上的会话的。
- 会话离开屏幕时（被替换、被关掉），它的页面会交给 `host` 在后台重新加载一次，前提是这些页面仍在
  「最近看过」的范围内。改之前也是这样。
- 看插件、拉取请求、已安排页面时，工作区仍在后面运行（第八条），正在流式输出的转录也照常渲染。
  这和打开设置时整个外壳的状态一样，代价是这段时间 React 仍在为看不见的内容工作。

**要小心的**：

- 往面板里读数据时，**先问自己在哪一屏**（`useScopedSessionId` / `useDockScope`），不要读
  `activeSessionId`。后者只回答「焦点在哪」，而同一时刻屏上可能有四个会话。
- 新增的入口如果需要打开面板，走 `openScopedPanel(kind, beside, 会话 id)`，让它去找那个会话的屏。
  不要直接调 `usePaneDock.open(currentScope(), …)`：那样会开在焦点屏上，而焦点屏未必是这个会话的。
- **空白对话那一屏也是一屏。** 它只在「台上」（`activeSessionId`）也是空白对话时才读台上那一份；
  旁边的会话占着台上时，它读到的是空白状态，而不是那个会话的运行状态、停止按钮和项目。点它
  （`focusPane(null)`）会把空白对话请回台上，项目用它自己开出来时的那个（`parkedDraft`），分屏保留——
  只有侧栏的「新对话」才是「下一句话独占屏幕」。
- **这一屏的项目读 `useScopedWorkspace()`，不读 `workspace`。** 后者只描述台上那个会话；两个项目的
  会话并排时，输入框上方的项目行、改动统计、终端的起始目录都要各报各的。
- **动作要指名这一屏。** 发送走 `send(…, { sessionId })`，空白屏指名 `null`——不写就等于「台上那个」，
  从前在空白屏里打的字就这样发给了旁边有焦点的会话。键盘能不经鼠标按下就够到一屏里的控件，焦点不会
  先切过来；需要先把这一屏请上台的动作用 `focusScreenOf(会话 id)`。
- **往输入框里放的草稿也要指名。** `setComposerDraft(text, { sessionId })` 的 `sessionId` 必填，只有
  那一屏的输入框会接。草稿槽整个窗口只有一个，而分屏时每一屏都挂着输入框——从前不指名的草稿在同一次
  提交里被每一屏各接一份：空白屏上按一张建议卡片，字同时出现在旁边那屏，光标落在最后接的那一屏。
  接下草稿的那一屏不在台上时，会顺手 `focusScreenOf` 把自己请上台：光标去了哪一屏，台上就是哪一屏，
  键盘路径和鼠标按下落到同一个状态。
- **菜单打开之后读的、改的，也是这一屏的。** 分支、模型、推理强度的菜单挂在每一屏的输入框上；读台上那
  一份时，键盘在旁边那屏打开的菜单列的是焦点会话的分支和模型，选下去改的也是它——在别人的仓库里
  `git switch`。store 的动作跟着指名：`setModel(…, { sessionId })`、`setThinking(…, sessionId)` 像
  `editMessage` 一样先把那个会话请上台；`refreshWorkspace(path)` 把这个项目在台上和 `workspaceByPath`
  里的两份一起重读，`switchingBranch` 带着仓库路径，只有那一屏的分支按钮转圈。
- **运行行的每一项都按屏取。** 时钟和 token 读 `turns[会话]`（`useScopedTurnMeter`），「正在做什么」读
  这一屏的 `toolRuns`，重连和「已压缩」也各记各的——`compactedAt` 跟着会话进出缓存。
- **文件树按项目并存。** `useFileTreeStore` 不再只认一个项目、换一个就清空：每棵树用 `show(roots)` 说明
  自己的源文件夹，刷新、全部收起、定位都只动这一棵的。`useProjectFolders(workspace)` 必须传项目，Files
  面板、文件名下拉、`@` 菜单传的都是这一屏的。打开的文件（`useOpenFile`）仍然整个窗口一份。
- **从一屏里打开另一个会话，开在这一屏。** 消息上的会话胶囊、轨迹里的「从这里分叉」都调 `openSession`，
  而分屏把台上换来的会话放在有焦点的那一屏：鼠标按下先把这一屏请上台，所以换掉的是按下的那一屏；键盘
  不经那一下，换掉的是旁边有焦点的那一屏。规矩（2026-09-27 定）是和鼠标一样——先 `focusScreenOf(这一屏)`
  再打开：换掉这一屏，或者目标已经在别的屏上时，焦点移过去。
- **项目菜单在打开之前就请上台。** 选一个项目、「不在项目中工作」都作用于台上：空白屏旁边的会话占着台上时，
  从空白屏的项目按钮选下去，是从那个会话开「新对话」——分屏里所有其他屏跟着关掉，空白屏自己也在内。
  按钮先 `focusScreenOf`，菜单勾的也读 `useScopedWorkspace()`。
- **交付审核一个会话一份。** `useDeliveryReview` 按会话记（`reviews[会话]`）：一屏打开审核不再关掉另一屏
  开着的那份，卡片上的撤销也只动自己会话的、而且只在它正显示这一轮时。审核面板里的文件名按
  `useScopedProjectPath()` 截相对路径。
- **面板窗口的请求带上它出身的那一屏。** 面板窗口没有 dock，`openPanelInMain` 把请求转给主窗口；它要带
  `scope`（`bootWindow.panelScope`），不然开在主窗口此刻的焦点屏。文件面板还要带要打开的那个文件——面板
  窗口的 `useOpenFile` 是它自己的，从前主窗口开出的文件面板显示的是它原来那份，或者什么都没有。
