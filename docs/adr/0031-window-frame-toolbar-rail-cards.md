# ADR-0031：工作区窗口走一套外框——顶栏、图标栏、卡片

- 状态：已采纳
- 日期：2026-10-05
- 相关：`app/window/WindowFrame.tsx`（`WindowFrame`、`MainToolbar`、`useNavShortcuts`）、`app/window/AppRail.tsx`、
  `app/nav-history.ts` 与 `lib/nav-history.ts`、`features/split/SplitChrome.tsx`（`ToolbarScreenTitle` / `ToolbarScreenTools`）、
  `app/layout.tsx`（`framed`、`toolbarHeight`、`rail`）、`shared/window-chrome.ts`（`MAIN_TOOLBAR_HEIGHT`）、
  `features/sidebar/NotificationsMenu.tsx`；ADR-0023

## 背景

用户给了一张参考截图：窗口顶上横贯一条工具栏（红绿灯、后退、前进、侧栏开关，单个会话时它的标题），左边一列图标，
侧栏和内容都是工具栏下面的卡片。

我们原来的做法是把窗口顶行「分给」各块：红绿灯画在侧栏左上角，侧栏开关浮在角上，会话的标题栏就是它那张卡片的
第一行，整排往下挪 5px 去和卡片对齐（`MAIN_WINDOW_ROW_OFFSET`）。于是每张碰到窗口角的卡片都要给红绿灯或
Windows 的系统按钮让位（`startInset`、`cornerReserved`、拉取请求页的 `prInsets`），而且这套让位规则在 macOS 和
Windows/Linux 上是两条路径。

## 决定

1. **顶栏属于窗口。** 主窗口在所有桌面平台上都画一条顶栏：macOS 40px（红绿灯居中，y=13），Windows/Linux 沿用
   原生 header 的 32px。顶栏下面的东西一律不再为窗口的角让位——`layout.tsx` 的 `framed` 和 `headerBar` 一样被
   当作「上面有一条带子」读。会话窗口、面板窗口不变，仍是自己的 44px 标题栏。
2. **单屏时标题进顶栏，多屏时各屏自留。** 只有一屏时，它的标题和「…」画在顶栏里、对齐对话卡片的左缘，面板按钮
   在顶栏右端，对话卡片里不再留 44px 标题栏（`DockPane` 的 `reserveHeader`）。两屏以上每一屏仍是自己卡片里的
   标题栏——顶栏只有一条，说不清是哪一屏的。面板始终在顶栏下面，所以「标题栏不盖面板」那条规矩照旧成立。
3. **图标栏放去处，侧栏放会话。** 对话、拉取请求、已安排、插件四个去处和设置、更新提示进图标栏；侧栏留新对话、
   项目/聊天列表和座右铭。窗口窄到侧栏变成抽屉时没有图标栏，这些去处回到抽屉里，抽屉从顶栏下面开始。
4. **后退和前进是真的。** 历史记录观察 store 里的「视图 + 当前会话」，而不是让每个打开会话的地方自己报告；
   规则（同一处只记一次、往回走之后新去一处会截掉前面的、删掉的会话和已经不在的空白对话跳过）在
   `lib/nav-history.ts`，有单测。⌘[ ⌘]（Windows/Linux 上 Alt+←/→）和鼠标侧键也走它；在输入框里不触发。
5. **面板默认分栏，不默认标签页。** 标签页排法下面板没有拖动把手，也就拖不到对话的另一侧——这是人对终端和浏览器
   最先想做的事。标签页留在外观里，一步就能切过去。
6. **铃铛有用了。** 它从 09-07 起就是一颗没有任何处理的按钮；现在列出等你批准、出错、已完成的会话（当前这一屏
   除外）和没看过的定时任务失败，点一行去那里。

## 后果

- 窗口角的让位逻辑在桌面上只剩一处：顶栏自己的 `titlebar.start` / `titlebar.end`。`startInset` 等仍在，给手机那条
  没有顶栏的路径用。
- 侧栏是一张卡片：底色取窗口色和内容卡片之间的一档（毛玻璃下是半透明的纸），三层读得出来。
- 设置页走同一套外框，从对话切到设置时动的只有内容。

## 什么时候该重新考虑

- 如果多屏也想把「当前那一屏」的标题放进顶栏：要先回答顶栏标题和每屏自己的标题栏怎么不说两遍。
- 如果标签页排法要成为默认：先让标签能拖出来、能拖到另一侧，再换默认。
