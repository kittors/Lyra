# ADR-0005：打 tag 直接发布，不留草稿

- 状态：已采纳
- 日期：2026-09-03（追记）
- 相关：`.github/workflows/release.yml`

## 背景

发布流程原本把三平台的产物汇总成一个**草稿** release，留出读一遍说明再手动 Publish 的余地。

结果是 0.4.0、0.4.1、0.5.0、0.6.1 四个版本全都躺在草稿里。产物齐全、上传完毕、谁也下载不到。
更新检查会跳过草稿和预发布，所以那是四个什么都没发出去的「发布」。

## 决定

tag 推上去、三平台绿了就直接发布。

## 后果

推一个 tag 本来就已经是「决定发布」这个动作了。说明写错了事后还能改；一个没人能下载的版本，
事后改不了。

**最后一步如果是手动的，它就是会被忘的那一步。** 这条判断后来又用了一次：`pnpm release` 现在
自己检查「这个提交有没有绿色的 dry run」，而不是靠 AGENTS.md 提醒人去跑。见
[ADR-0010](0010-updates-are-verified.md) 里同样的取舍。

代价是没有「发布前最后看一眼」的关口。补偿它的是 `Release dry run`：同样的 runner、同样的
步骤、同样的顺序，只差最后不发布。
