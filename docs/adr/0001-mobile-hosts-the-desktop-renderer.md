# ADR-0001：手机跑桌面端的界面，不自己画一套

- 状态：已采纳
- 日期：2026-09-03（追记，实现于 v0.8.36）
- 相关：`packages/desktop/electron/sync-app.ts`、`packages/mobile/src/bridge.ts`、`packages/mobile/app/desk.tsx`

## 背景

移动端最初是一套用 React Native 写的独立界面：自己的会话列表、自己的分组规则、自己对
「一条消息该长什么样」的理解。它与桌面端共享的只有会话日志的格式。

代价出现得很快。桌面端加一个功能，手机上没有；手机上修一个显示问题，桌面端不受益；两边
对同一份数据的呈现开始分叉。而手机那套永远落后——它是同一个人在业余时间维护的第二套 UI。

## 决定

手机不再自己画。它在 WebView 里加载**桌面端的那一份界面**，从配对的那台机器上取。

`bridge.ts` 在页面加载前注入一段脚本，用 HTTP 加一个 WebSocket 重新实现 `window.lyra`。
界面只认识这一个东西，所以它察觉不到自己跑在哪里。

## 后果

**得到的**：两端由构造保证一致，不靠纪律。桌面端更新了，手机下次加载就是新界面，中间没有
应用商店。界面的任何改进自动惠及两端。

**接受的代价**：

- 手机必须能连上桌面端才有界面。离线不可用——但离线本来也没有 agent 可用。
- 加载的是同一份 bundle。局域网内没问题，走中转跨公网就是几兆的传输，见
  [ADR-0002](0002-relay-knows-nothing.md) 与那里的取舍。
- 手机能调的方法必须显式列白名单（`sync-rpc.ts`）。界面是全的，能力不是——终端、写文件、
  截图都不在名单上。不在名单上的方法，界面自己降级。

**同源不是附带的好处。** 界面由同步服务自己提供，所以渲染进程 CSP 里的 `connect-src 'self'`
中的 self 就是同步服务，它的 fetch 与 WebSocket 天然被允许。把界面打包进 App 反而要授权它
连接任意主机——那是宽得多的一道门。

## 什么时候该重新考虑

如果手机需要在完全离线的情况下查看历史会话。那时要的不是「自己画一套」，而是把这一份界面
在本地缓存起来，仍然是同一份代码。
