# ADR-0025：一轮之内换模型，从下一个请求起就换；卡在重试上的请求当场放手

- 状态：已采纳
- 日期：2026-09-25
- 相关：`packages/core/src/agent/loop.ts`（`LiveModel`、`streamTurn` 的 `switchAbort`）、`runtime/session.ts`（`liveModel`、`adoptModel`）、`runtime/turn-config.ts`、`agent/events.ts`（`retry_settled` 的 `switched`）、desktop `lib/hiccup.ts`、`features/conversation/HiccupTrace.tsx`

## 背景

用户反馈原话：「对话 a 以模型 a 请求发出去之后，一直响应有问题（上游问题），我就在对话框的位置切模型
b，然后直接点对话 a 下面的编辑、打勾重发，这时请求的还是之前的模型 a；我重新复制，从对话框输入，这时
才是模型 b 请求。」

core 层按三种时序、在 v0.9.0 到 main 的六个版本上复现，编辑重发一直读的是会话当前的模型——那一步
没错。照原话在真窗口里走一遍（`e2e/edit-resend-model-probe.ts`，上游重试按反馈者本机配成
`retries: null`，也就是一直重试到取消）才量到问题在编辑之前那一段：

| 步骤 | 服务器收到的 |
| --- | --- |
| 用 a 发出去，上游一直 502 | a, a, a |
| **重试中切到 b（输入框已写着 Model B）之后 3.5 秒** | **a, a, a, a** |
| 停止 → 编辑 → 打勾重发 | b |

一轮开始时拿到的模型用到这一轮结束。而重试设成「一直重试到取消」时，这一轮永远不会自己结束。人换
模型恰恰是为了躲开坏掉的上游，看到的却是「请求的还是 a」。

同样的事，重试策略早就处理过：它是每次重试前现读的（`RetryPolicySource`），理由写在那里——一个
一直在重试的请求会活过好几次设置页的修改。模型是同一个道理，只是没人这样做。

## 决定

1. **模型每个请求现读。** 循环拿到一个 `LiveModel`（会话给），每轮开头问一次「现在该用哪个」；变了就从这个
   请求起换过去。
2. **卡在重试上的请求当场放手。** 请求层订阅「模型变了」：还什么都没说出口的请求（在连、在重试）被放手，
   回到循环顶上用新模型从同一处重发。已经在出字的不动——它在干活，说完了下一个请求自然用新的。
3. **放手不是停止。** 用单独的控制器，不跟 `config.signal`（人按了停止）混：与规则打断同一个模式。被放手
   的请求什么都不进转录，不算一轮。
4. **换人之前摘句柄。** 手上的历史全出自旧模型，供应商句柄交给新模型只会被整条拒掉，按「切换那一刻之前
   的都剥」来（不按每条消息的 `model` 字段比：有的供应商回报的模型名跟配置里对不上，逐条比会把同一个
   模型自己的思考签名剥掉）。循环真正换过去时回调 `adopted`，会话把日志里的切换位置挪到此刻——人按下
   切换和循环真正换过去之间旧模型说完的那一句，也一样被摘。
5. **重连那一行说实话。** `retry_settled` 多一个 `switched`（带 `switchedTo`）：界面写「重试 N 次后换成
   Model B 接着问」。它既没有恢复也没有放弃，说成哪一样都是在报一件没发生的事。
6. **后派的子代理跟着新的走。** `spawnSubAgent` 派出去那一刻现读。

## 没有做的

- **不打断正在出字的请求。** 那会扔掉说了一半的话、再花一次钱重问。
- **不在每个请求都按消息剥句柄。** 理由见上面第 4 条。
- **子代理、侧聊、评测不接 `liveModel`。** 省略就是整轮不变，行为跟从前一样。

## 后果

- 真窗口（`e2e/edit-resend-model-probe.ts`）4/4：重试中切到 b，433ms 后 b 的请求就出去了，之后没有再
  请求一次 a；这一轮直接由 b 答完，不用停止、不用编辑；重连那一行写「重试 5 次后换成 Model B 接着问」；
  之后编辑重发也是 b。修复前同一个探针量到的是 a, a, a, a。
- 单测（`live-model-switch.test.ts`）走真实适配器和本地服务器：放手换人、按停止仍是停止、在出字的不打断、
  请求之间换人并摘掉旧句柄、不给 `liveModel` 时一切照旧。
- 代价：循环每轮多一次 `current()`（一次查表）；请求层多一个订阅。
