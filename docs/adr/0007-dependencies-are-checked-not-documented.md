# ADR-0007：依赖方向由机器检查，新规则先报告后阻断

- 状态：已采纳
- 日期：2026-09-03
- 相关：`.dependency-cruiser.cjs`、`ARCHITECTURE.md`

## 背景

这个仓库的边界是真的、想清楚过的，也写下来了。AGENTS.md 说 core 平台无关；`core/src/index.ts`
的注释解释了从根入口导入*值*会把 `node:fs` 拉进浏览器包，窗口一片空白。

缺的只是「有人越过时会发生什么」——答案是不会发生任何事。而这类越界的共同点是：类型检查是绿
的，测试是绿的，坏掉的是运行时，而且往往在另一个平台上。

## 决定

dependency-cruiser，`pnpm arch`，进 CI 的必过项。

关键能力是它能区分 `import type` 与值导入（`tsPreCompilationDeps: "specify"`），所以「类型免费、
值不免费」这条能真的表达出来，而不是只能全禁或全放。

规则见 ARCHITECTURE.md 的「边界」一节。每一条都造过一次违规验证它真的会红。

## 后果

**新规则先 warn，清零的那次提交里再转 error。**

第一次跑出 79 条违规，其中 53 条是值层面的循环依赖。上来就红只会有两种结果：先花一周解开它们，
别的规则一条都进不去；或者更可能的，整个工具被无视。knip 在这个仓库里用 `--no-exit-code`
就是同样的判断。

所以现在 error 的是当前为零的那几条——它们不能倒退；循环是 warn，数字在输出里，会随着功能域
各自成目录往下走。

类型层面的循环被排除掉了。`Message` 引用 `Provider` 再引用回来是正常的 TypeScript，编译期就
没了，为了让工具满意去压平一个类型模型是本末倒置。
