# ADR-0016：视觉改动必须看一眼，并且逐像素对照

- 状态：已采纳
- 日期：2026-09-03
- 相关：`packages/desktop/e2e/styles-alive.test.ts`

## 背景

一次 `stylelint --fix` 把 `@import "tailwindcss"` 改写成了 `@import url("tailwindcss")`。两种
都是合法 CSS，只有前一种是 Tailwind 自己的解析器认得的形式，于是它一条工具类都没生成，整个
应用塌成一列没有样式的东西。

**没有任何一道检查发现它。** 构建成功。类型通过。2105 个单元测试通过。30 条端到端测试通过——
它们点按钮、读文字，而没有样式的按钮照样能点。

唯一发现它的方式是打开看一眼，而那次没有看。

## 决定

两条，都不是「更仔细一点」这种嘱咐：

**`e2e/styles-alive.test.ts`** 断言样式坏掉时伪造不了的东西：工具类必须真的生成了规则、token
必须解析出值而不是空串、外壳必须有背景、布局必须是横排而不是单列。

**逐像素对照**：改动视觉相关的东西之后，起真窗口截图，和改动前的基准比 SHA。相同才算完成。

## 后果

第一条写的时候第一版就是错的——顶层遍历 `cssRules` 看不到 `@layer utilities` 里的工具类，于是
它在样式完好的时候也报红。改成递归查找，并且**把那个 bug 重现一次验证它会红**：四条里三条同时
失败。一条没验证过会失败的测试不算测试。

第二条在这次重构里跑了三遍，三次 SHA 都与起点一致。

**为什么值得**：这个项目里样式和交互不是附加值，是产品本身。一次静默的样式故障比一次崩溃更糟
——崩溃会被报告，而「界面变丑了」只会让人默默关掉。
