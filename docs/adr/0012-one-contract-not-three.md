# ADR-0012：进程边界写在一处，不是三处

- 状态：已采纳
- 日期：2026-09-03
- 相关：`packages/contract/`、`packages/desktop/electron/sync-rpc.ts`

## 背景

同一件事有三处描述，互相之间没有共同来源：

| 文件 | 说的是 |
| --- | --- |
| `ipc-types.ts`（925 行） | 方法的类型签名 |
| `preload.ts`（157 个 invoke） | 方法名到 channel 名的映射 |
| `sync-rpc.ts` | 手机能调哪些 |

加一个方法要改三处。漏掉哪一处，表现各不相同：

- 漏 `preload` → `undefined is not a function`，一眼能看出
- 漏 `ipc-types` → 类型报错，编译期就挡住
- **漏 `sync-rpc` → 手机上静默失效**：界面在，点了没反应，没有任何报错

第三种是最贵的，因为它只在手机上出现，而开发是在桌面上做的。

## 决定

`@lyra/contract`：157 个方法写在一处，每个带 channel 名和「手机能不能调」。后者为 false 时
**必须附一句为什么**——这是安全边界，一个光秃秃的 false 读起来像是忘了加。

十条测试守着它与那三个文件的双向一致。

## 后果

**得到的**：加方法时漏掉白名单不再可能——契约里每个方法都必须显式声明 remote，没写编译不过；
写了但 `sync-rpc` 没实现，测试会红。

**顺带发现的**：提取清单时，正则一开始漏掉了四个参数换行的方法，而其中两个正是手机在用的。
那正是三处分开维护会漏掉的东西。

**没做的**：参数的运行时校验（zod）。契约现在描述「有什么」，不描述「参数长什么样」——手机那
条路径的输入来自网络，这一层仍然缺。下一步应该是它。
