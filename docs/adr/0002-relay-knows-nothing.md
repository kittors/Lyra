# ADR-0002：中转服务不知道令牌，房间号是它的哈希

- 状态：已采纳
- 日期：2026-09-03（追记，实现于 v0.8.36）
- 相关：`packages/relay/server.mjs`、`packages/desktop/electron/sync-relay.ts`

## 背景

局域网配对要求两台设备在同一个网络里。出了门就不成立：手机在流量上，电脑在家里的路由器
后面，双方都没有对方能拨到的地址。公网反代能解决，前提是你已经有域名、有反代、有一条打得
进来的端口转发。大多数人没有。

## 决定

一个只做一件事的 WebSocket 中转：**两端都主动往外连**它，它把两条连接接在一起。出站连接
不需要端口转发，所以 NAT 后面也能用。

关键是它知道什么。房间号是配对令牌的 SHA-256，**令牌本身不出现在任何发给中转的消息里**。
所以中转知道「有两个客户端想凑到一起」，既不知道它们是谁，也不知道它们说了什么。

一个房间最多两人，第三个直接拒绝。房间号是从令牌派生的，出现第三个意味着令牌泄露了——此时
把它挡在外面，比让它挤掉真正的设备更合适。

## 后果

**得到的**：一个可以放心自建、也可以用别人的服务。运营者拿不到任何有意义的东西。

**接受的代价**：

- 这**不是加密**。中转仍在明文路径上，能看到 WebSocket 帧的内容。它只是不需要知道，也没有
  被告知。真正的机密性来自部署时套的 TLS。
- 走中转要传两次公网：桌面端上行 → 中转 → 手机下行。加载界面那几兆在这条路上最贵。
- 中转不缓存、不重排、不落盘，所以它挂掉就是断线，没有中间状态可恢复。

## 什么时候该重新考虑

如果要给中转加账号或计费，先想清楚那会让它知道什么。它现在的价值恰恰在于什么都不知道。
