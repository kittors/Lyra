# ADR-0037：切到独立页，代码先到、版只排一次

- 状态：已采纳
- 日期：2026-10-13
- 相关：desktop `app/screens.tsx`、`app/screen-reach.ts`、`app/window/AppRail.tsx`、`app/panes.tsx`（`SLIDING_EDGE`）、`ui/layout/settled-width.ts`、`features/gallery/GalleryGrid.tsx`、`features/gallery/store.ts`；测试 `test/ui/settled-width.test.ts`、`test/ui/preloaded-screens.test.ts`、`test/ui/gallery.test.ts`；探针 `e2e/gallery-switch-probe.ts`；ADR-0017、ADR-0034

## 背景

用户反馈切到「创作」不流畅、有性能问题，附了一段录屏。逐帧看录屏，点下去到画面变化只有 50–200ms，帧率也
稳——慢的不是响应，是**画面在动**：进创作要把会话侧栏收起来（`app/layout.tsx`），侧栏是 `margin-left`
过渡，旁边的内容区在 220ms 里每帧一个宽度；相册是按宽度排的对齐网格（`justify`），于是每帧重排一次。
在本机真实数据上量：每次进入每张图 13 种尺寸、126 次样式提交，CPU 降速 4 倍时首帧是 50–67ms 的长任务。

第一次进入还有另一件事：点下去 43ms 出骨架，到 355ms 页面才挂上。读列表只要 52ms，54KB 的分包几毫秒就到，
多出来的 300ms 是 React 19 的回退节流——骨架一旦露出来，内容至少等 300ms 才能换上去
（`globalMostRecentFallbackTime + 300`）。插件、拉取请求、已安排、设置第一次打开是同一回事。

## 决定

**一、跟着宽度排版的东西，在侧栏滑动期间按滑完的宽度排，只排一次。** `useSettledWidth`
（`ui/layout/settled-width.ts`）：侧栏外框挂 `SLIDING_EDGE` 标记；量宽度时如果它上面有过渡在跑，就把每个过渡
拨到终点、读宽度、再拨回原处，同步完成，中间不画任何一帧；这一次滑动里不再量，滑完再按当时的宽度量一次。

拨动动画之前先在 Electron 的 Chromium 里量过：拨回之后过渡从原来那一帧接着走（12 帧，321 → 49 平滑），
`finished` 不会提前兑现（结束通知在微任务里会再查一次播放状态，那时已经是 running），也不派发
`transitionend`（拨动当下和之后两帧都是 0 次，结束时照常 2 次）。

相册因此在第一帧就是最终的版，跟着面板滑进来，伸出去的部分被滚动容器（本来就是 `overflow-x: hidden`）
裁掉，滑完正好对齐。

**二、整屏视图提前取。** `lazy` 自己做不到：它的 payload 只在第一次渲染时初始化，所以哪怕代码早到了，第一次
渲染也要挂起一次——挂起就有骨架，有骨架就有那 300ms。`app/screens.tsx` 给每个整屏视图包一层：代码到了就直接
渲染组件，没到才交给 `lazy`（它擅长的正是「代码真的还在路上」）。取的时机：

- 窗口空闲时取四个小的（14–130KB），一个空闲时段取一个；
- 设置页 3MB，解析它是一个长任务，落在点击底下正是要去掉的那种卡顿，所以只在指针停到图标栏按钮上
  （或键盘聚焦）时取；
- 手机上都不预取：那里的包要过中转，没人要的四个页面会排在人等着的东西前面；
- 创作页在指针停上去时顺手读一次列表（首读要把每个画过图的会话加载一遍，是主进程的时间，不在空闲时花）。

图标栏不直接引 `screens.tsx`：图标栏由窗口外框画，设置页也画窗口外框，而设置页是 `screens.tsx` 要加载的一屏，
直接引会成环。中间隔一个 `screen-reach.ts`：图标栏说「有人伸手了」，`screens.tsx` 在挂载时登记谁来听。

**三、读回来的列表没变，就沿用手里那份。** 页面隐藏时监听是关着的，所以每次进来都要再读一遍；几乎每次读到的
都是原样，而一个新对象会让相册里每一块都重画。比较 JSON 文本（几百张图也是毫秒以内），只有它和手里那份
确实对应时才沿用。

## 后果

同一版探针（`e2e/gallery-switch-probe.ts`，本机真实数据副本，8 件作品）量改前改后：

| | 改前 | 改后 |
|---|---|---|
| 再次进入：一张图的尺寸变化 | 13 次 | 0 次 |
| 再次进入：布局 | 29 次 | 17 次 |
| 第一次进入：页面挂上 | 355ms | 27ms |
| 第一次进入：图全部出现 | 405–426ms | 109ms |
| CPU 降速 4 倍：主线程合计 | 284–361ms | 271–277ms |
| CPU 降速 4 倍：最长一帧 | 52–67ms | 35–48ms |

常速下交替各跑 8 次的中位数：主线程 209ms → 195ms。

**没解决的：** 每次切换主线程还有约 195ms，大头是侧栏的 `margin-left` 过渡本身——每帧都要在主线程上重排、重绘，
不可见的会话区（`Workspace` 离场时是 `absolute inset-0`）也跟着每帧变宽，里面输入框的渐隐（`useFieldFade`）
每帧强制读一次布局。要去掉得把侧栏改成合成器上的 `transform` 动画，影响到每一处开合侧栏，没有放在这次。

图标栏之外的入口（窄窗口抽屉里的导航）没有悬停预取，靠空闲预取覆盖；设置页从那些入口第一次打开仍会看到骨架。
