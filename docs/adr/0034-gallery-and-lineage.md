# ADR-0034：画廊——跨会话列出画过的图，生成链路按图片内容连起来

## 背景

用户要的是：图标栏里一个画廊，所有对话里画过的图像相册一样排开；点开能看这张图的详情，以及它是怎么一步
一步改成现在这样的（连线画出来）；能从图直接回到对话里画它的那个位置；能就着这张图快速再改一次——写一句话，
或者先在图上圈出来。

`image_generate` 的结果只记了 `edit: true`，没记改的是哪张。

## 决定

1. **图按 `session-media` 里的名字认，那是内容的哈希。** 分叉复制过去的、被附进另一个会话再改的，都是同一个
   节点，链路跨会话自然接上。一张图出现在好几个会话里，算在最早创建的那个会话名下——分叉一定晚于原会话，
   而分叉没有留下复制标记（ADR-0032）。
2. **新的结果记下输入（`sources`）；旧结果从调用参数倒推。** `#N` 按工具当时的同一条规则在调用所在那条消息
   之前的对话里数（`conversationPictures`）；同一条消息里并列的几次调用互相看不见对方的图，倒推时也不算。
   指向 `session-media` 的路径按文件名认；工作区里的文件倒推不了，记成「找不到原图」而不是猜。新结果里，
   工作区的图按哈希存一份进 `session-media`，文件之后改了，链路照样画得出起点。
3. **标注副本是新字节，所以图片块带 `from`。** 从画廊或对话里的图标注、交给输入框的那张，记着它是从哪张
   标注来的；这个字段只给界面看，三家适配器都只取 `data` 和 `mimeType`，不会发出去。主进程的白名单只收
   `session-media` 的文件名。链路因此穿过「在图上做了标注」那一步，不在标注处断开。
4. **主进程按需扫库，每个会话按 `seq` 缓存。** `sessionsWithResultOf` 在记录正文上做 `LIKE` 预筛（转义了 `_`，
   否则 `imageXgenerate` 也算）：在一份真实历史的副本上（12.6k 条记录、23MB 正文）10–20ms，所以不做增量；
   按 `records.id` 增量还会漏行——删掉最新的会话以后 id 会被复用。命中的会话用 `load(…, {display:true})` 读
   ——撤回的部分已经去掉，像素不进内存——没写过的会话不重读。删掉的会话连同它的图一起从画廊消失（文件还在
   磁盘上，`session-media` 本来就没有引用计数）。手机不开放：图走 `ly-media`，手机上没有这条路由。
5. **相册按天分组，每行等高、整行撑满，图按自己的比例。** 方块裁切会把 16:9 的图切掉一半；最后一行不硬撑。
   网格用 `?thumb=800` 的缩略图，懒加载。
6. **链路排成一列。** 先走完一条改下去的路线，再列另一条分支；上下相邻的两步用一段短直线连，其余（第二次
   改同一张图、两张合成一张）从图的左边缘出来，沿左侧圆角括线拐进它连到的那张；当前这张的来路用强调色。
   第一版是按时间排、分支挪到第二条道上——缩略图左右错位、文字起点忽前忽后、分叉的线贴着别的图擦过去，
   黄昏那条分支被夹在夜晚和冬夜中间。用户看了说「非常丑」，改成现在这样。
7. **画廊里不显示会话侧栏。** 画廊是一个独立的去处，列表只是把相册挤窄。进画廊时收起，离开时恢复成原样；
   画廊里点侧栏按钮只在这一趟里打开，不改别处的样子。打开的大图盖住整块面板（图标栏除外）。
8. **「在对话中查看」是一个请求，不是一次调用。** 会滚动的东西——转录的窗口、跟随底部的状态——都在
   `Conversation` 里，而画廊发出请求时那个对话可能还没打开、还没读完。请求放在 store 里，对话读完后自己取：
   展开到那一轮、脱离跟随底部、把图滚到中间、图框闪一下。
9. **二次编辑发回图所在的对话，带原图本身。** 字节原样回去，所以附件就是同一个 `session-media` 文件，新图
   的来源直接连到它。有字时直接发——输入框的草稿多了 `send`，**只在输入框原本是空的时候**才自动发：别人
   写了一半的话不能被一起发出去，那时候就照普通草稿落进去，等人自己按发送。只有标注没有字时不自动发。
   新图画好、回到画廊时，详情直接换到新图上（等十分钟，模型反问而没画的那次不会在以后突然跳过去）。

## 没做的

- 子智能体画的图不进画廊：它们是父会话里的事件，跳过去要打开子智能体面板，而目前一张都还没有过。
- 不能在画廊里删图。图被多个会话共用，删除需要先有引用计数。
- 手机端。
- 缩略图沿用现成的 PNG 缩略图，一张 800px 的照片缩略图有几百 KB。

## 什么时候该重新考虑

- 有人的历史大到预筛要上百毫秒：改成按每个会话的 `seq` 增量读，不要按 `records.id`。
- 一家子的分支多到左侧括线超过四五道：考虑把与当前这张无关的旁支折叠起来。
